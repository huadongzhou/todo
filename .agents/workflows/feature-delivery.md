# 跨端待办应用功能交付流程

本流程服务于待办应用的研发，不是独立项目。

## 选择流程

| 任务类型 | 使用流程 |
| --- | --- |
| 新功能、跨端交互、数据/API/权限变更 | 标准流程 |
| 仅文本、颜色、间距、图标或已有组件展示调整 | 轻量流程 |

## 轻量流程

```text
需求确认 → 开发 → 轻量验证 → Code Review → 完成
```

适用于不涉及数据模型、API、权限、路由或产品流程的简单显示改动。

角色只能在 `task.json` 的 `skipped_roles` 中记录角色、原因、影响评估和替代证据后跳过。产品验收、验证和 Code Review 不应跳过，但可以缩减范围。范围、权限、数据、付费或生产发布有不确定性时，必须人工确认。

## 状态流

```text
intake → product_ready → design_ready → architecture_ready → implementation
  → qa → review → release_ready → done
                 ↘ blocked / rework（退回责任角色）
```

## 阶段与交接条件

| 阶段 | 责任角色 | 必须产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| intake | 产品 | 初始需求与约束 | 有任务 ID、目标与优先级 |
| product_ready | 产品 | `prd.md` | 用户故事与验收标准可测试 |
| design_ready | UX/UI | `design.md` | 覆盖核心流程、状态、响应式与无障碍要求 |
| architecture_ready | 架构 | `architecture.md` | 边界、数据/API、风险和验证方案明确 |
| implementation | 开发 | 代码、测试、`implementation.md` | 本地构建与相关测试通过 |
| qa | QA | `qa-report.md` | 验收标准逐项验证；缺陷已修复或获批准 |
| review | 代码审查 | `review.md` | 无未解决的阻断或高优先级问题 |
| release_ready | 发布 | `release.md` | 发布步骤、监控与回滚准备就绪 |
| done | 编排者 | `task.json` | 所有门禁均为通过 |

## 退回规则

1. 发现需求缺口，退回产品角色。
2. 发现流程或视觉规格缺口，退回 UX/UI 角色。
3. 发现技术不可行或契约冲突，退回架构角色。
4. 测试失败或缺陷未修复，退回开发角色。
5. 每次退回在 `task.json` 的 `history` 中记录日期、原因、证据与下一位负责人。

## 最小交接规则

每个阶段结束时，仅追加一条 `handoff.md` 记录，包含：当前角色、下一角色、已完成产物、必读文件、下一步任务、验收条件、未决问题。不得把整段对话或重复背景复制进去。

下一角色必须先读取最新交接记录和其中列出的文件；范围、权限、生产操作或数据处理存在重大不确定性时，标记为阻塞并要求人工确认，不得自行假设。

## 人工门禁

以下操作必须由人确认：需求范围变更、设计定稿、合并主分支、生产发布，以及对高风险审查项的例外批准。
