## 需求（产品）

- 目标与场景：同一任务可设多个提醒点（如截止前 1 天 / 1 小时 / 15 分钟），每个提醒点各自按时触发。
- 范围（做 / 不做）：做 契约从单值 `reminder_at` 迁移到多提醒点列表（或等价形态）+ 多提醒点的设置界面 + 各点触发；不做 时区策略（07）、不做 移动端本地通知（2.3）。
- 外部前置：01（调度底座，已完成）。与 07（时区）无强制先后——但两者都改调度/契约，注意改动交接（先落地者在实现记录写清，后者对齐）。
- 验收标准（逐条可检查）：
  - [ ] 一个任务可设多个提醒点，全部按时各自触发（含 01 的驻托盘/重启补发、04 重催/05 勿扰/06 摘要对多提醒点的既有行为不回归）。
  - [ ] 契约迁移无损：既有单值 `reminder_at` 数据升级到新形态不丢；同步双端一致；`src/bindings/` 重生成、全调用方（含 snooze 改 reminderAt、01 的 due_reminders、04/05/06 的投递键）同步。
  - [ ] 多提醒点在统一创建界面/编辑态可设可存可显（复用 02/03 的字段块形态，注意提醒此前是 03 的单值字段）。
  - [ ] `cargo test --workspace`、`pnpm run check` 通过；契约变更跑 `pnpm run types:generate` 并同步调用方。

### 0. 四个正面判断（正面表态）

| 议题 | 判断 |
|------|------|
| **a) 多提醒点放哪、什么形态：字段表 vs 编辑态兄弟区块？** | **留在字段表（`TodoFields`），做成一个「整对象/整列表」字段，走 `recurrence` 的先例——不是 Subtask/Attachment/Dependency 那样的编辑态兄弟区块。** 三个兄弟区块的自述理由（见 `AttachmentList.vue:20-29`、`DependencyList.vue:9-18`）恰恰**反证**提醒不该是兄弟区块：它们「只在编辑态、不进创建表单」是因为「附件/依赖挂在一个**已存在**的任务上」；而提醒相反——`任务管理/02` 明确把「提醒」列为创建界面三字段之一（`02` 范围表：`reminderAt` ✅ 做），用户是在**创建时**就说「提醒我」，提醒是任务日程定义的一部分、不是对已存在任务的追加。所以提醒必须同时出现在创建表单与编辑态，这正是「字段」而非「兄弟区块」的判据。关于「字段表 `control` 联合（input/textarea/range）表达不了一组可增删的行」——**联合里第四个变体 `recurrence` 就是这道逃生门**：`FieldControl`（`TodoFields.vue:195-207`）已有 `{ kind: "recurrence" }`＝「一个整对象、由自己的子组件编辑、不走字符串 `codec`」。多提醒点只是把这道门用在「列表形对象」上：新增一个 `{ kind: "reminders" }` 变体 + 一个模板分支 + 一个子组件 `ReminderField.vue`（骑草稿），与 `recurrence` 同构。理由见第 1 节。 |
| **b) 相对提醒（截止前 N）vs 绝对时刻 vs 两者** | **本任务推荐「一组绝对时刻」，相对「截止前 N」延后为独立产品决策（属需编排者/产品拍板的契约形态，见第 5 节）。** 两条硬约束把选择收窄：① **迁移无损要求绝对必须支持**——现状 `reminder_at` 是绝对 UTC 瞬间，单值→列表要无损，旧值只能落成「一条绝对时刻提醒」，故绝对时刻是列表元素的**必选**底座；② **相对提醒缺一个「带时刻的锚」**——需求例「截止前 1 小时 / 15 分钟」要求锚点有**时分**，但 `dueDate` 是纯日期（`YYYY-MM-DD`，`lib.rs:65-69` 注明「the due date stays a plain date」），「某天的 15 分钟前」无定义（那天几点截止？09:00？23:59？）。所以相对提醒不是「加个偏移量」这么小，它牵出「dueDate 要不要带时刻 / 是否改锚到 `startsAt`」的模型缺口，超出简化级、也超出本任务「单值→列表迁移」的范围。**推荐**：本任务只做绝对时刻列表，把「截止前 N」预设留给后续任务（若产品要现在就要，见第 5 节备选＝带载荷枚举，同时回答其两个附带问题）。 |
| **c) floating/absolute 与多提醒点：全局还是每点？** | **全局（承 07 裁决），不每点。** 07 已定并经编排者裁决：单个复选框、默认＝本地时刻 floating、放「提醒」`fieldset` 末尾。理由本任务复核仍成立——「按当地墙钟还是绝对瞬间理解我的提醒」是一种**跨全部提醒的心智模型**、不是逐条属性；每点各选＝每行多一个开关，为一个边缘语义在每行加控件属过度设计，且与简化级相悖。故：**全局一个开关管所有提醒点的解释；每个提醒点只存「墙钟 + 原始偏移」，不存自己的 floating 标志**（第 4 节数据期望）。 |
| **d) 迁移的用户可见影响** | **无感迁移，界面不告知。** 现有单个 `reminderAt` 升级为「列表里的一条」，编辑态打开时就显示为**一行**提醒、值与原来一致；不弹迁移提示、不加「已升级」横幅、不改到期徽标。全局开关默认 floating，迁移后的这条按其当前显示的当地墙钟继续 floating（旧数据无原始偏移可考，dev 按迁移当刻的设备偏移反解墙钟即可——那正是它此刻显示的时间，用户看不出任何变化；正确性边界见第 4 节）。 |

### 1. 结构与布局：多提醒点字段 `ReminderField.vue`（新增，创建与编辑共用）

**定位**：`TodoFields.vue` 字段表「时间」组里的一个 `col-span-full` 整行字段，`label`＝`提醒`，**取代**现有 `reminderAt` 半行字段（`TodoFields.vue:351-369` 那条 `kind:"input" type:"datetime-local"` + 「提醒时间已过」note 的定义整条删除，换成新字段）。组内位置不变（契约声明序：`dueDate → recurrence → 提醒`，`02` 规格已定组内顺序＝契约顺序）。

**它是 `recurrence` 的孪生，不是兄弟区块**——照抄 `RecurrenceField.vue` 的接线方式（`TodoFields.vue:979-987`）：
- 新增 `FieldControl` 变体 `{ readonly kind: "reminders" }`（`TodoFields.vue:195-207` 联合里加一支，与 `recurrence` 并列；联合注释里「已知的下一批」正是这种扩展）。
- `keysOf`（`TodoFields.vue:432-437`）加一支返回 `["reminders"]`（如 `recurrence` 返回 `["recurrence"]`）。
- `visibleGroups`（`TodoFields.vue:843-844`）的 `single` 判空路径把 `reminders` 一并纳入「无单一 `codec`」分支（与 `range`/`recurrence` 同路）。
- 模板加 `v-else-if="entry.kind === 'reminders'"` 分支，渲染 `<ReminderField :model-value="draft.reminders" :anchor="draft.dueDate" :field-id="entry.id" @update:model-value="onReminders" />`；容器经 `onReminders(list)` → `commitDraft({ ...pendingDraft, reminders: list })`（与 `onRecurrenceChange` 同型，`TodoFields.vue:709-712`）。`anchor` 现在（绝对时刻方案）用不上，预留给第 5 节备选；无阻塞校验故不需 `error-id`/`register-control`。

**为何是字段/骑草稿、而非兄弟区块/即时提交**：兄弟区块（Subtask/Attachment/Dependency）每次改动**直接落 store**（即时、各自一条撤销），因为它们只对已存在任务成立、且不该进创建表单。提醒字段**骑草稿**（改动经 `update:modelValue` 进 `draft.reminders`，随创建的 Enter / 编辑的「保存」整体落库，Esc/取消一并丢弃），与 `recurrence` 完全一致——因为创建时任务尚不存在，提醒必须先在草稿里成形；且提醒是任务原子定义的一部分，应随原子保存一起提交，不该像子任务那样即时落库。这是本字段与三个兄弟区块的**关键行为分野**，请开发照此，勿误接成即时提交。

**内部形态**（借 `SubtaskList` 的「行 + 添加触发器」视觉，但提交走草稿）：`ReminderField` 内是一个 `<fieldset class="m-0 border-0 p-0">` + `<legend>提醒</legend>`（照 `range` 字段的嵌套 fieldset 写法，`TodoFields.vue:953-954`；不是兄弟区块的 `<section border-t>`，因为它在字段表**内部**的组栅格里）。其下：

- **已设提醒行**（`draft.reminders` 每条一行，`grid gap-2`）：每行 `flex items-center gap-2` ＝ 一个 `datetime-local` 输入（在位可改，逐字复用 `CONTROL_CLASS`，换算复用 `toLocalDateTimeInput`/`toInstant`，本任务不新增换算函数）+ 一个删除按钮（`Trash2`，逐字复用 `SubtaskList.vue:379-387` 的 ghost 删除按钮类串：`min-h-11 min-w-11 shrink-0 !p-2 text-slate-400 hover:text-red-600 dark:hover:text-red-400`）。
- **该行的「已过」提示**（把原字段级 note 下沉为逐行）：该行时刻 < 当前时刻时，行下一条 `text-xs text-amber-700 dark:text-amber-300` 的 `提醒时间已过，保存后会立即提醒一次。`（文案与类串逐字沿用 `TodoFields.vue:363-368`+`1037` 的既有 note），经 `aria-describedby` 关联该行输入。非阻塞（过去提醒是合法意图、触发一次即止，与现状一致）。
- **添加触发器 + 添加输入**（镜像 `SubtaskList` 的空表/添加盒，`SubtaskList.vue:404-442`）：列表为空时只显示一个 `＋ 添加提醒` 触发器（ghost Button + `Plus`，逐字复用 `min-h-11 w-fit !justify-start !px-2 text-sm text-slate-500 dark:text-slate-400`）——空任务的编辑态/创建态仍是一眼干净，不预铺空行；点击后揭示一个空 `datetime-local` 添加输入并聚焦它，用户经原生选择器选定时刻（`change`）即**追加**进 `draft.reminders` 并**保留添加输入、复位待下一条**（与子任务添加盒「加完清空、可连加」完全同构）。有 ≥1 条时添加输入/触发器常驻其下。
- **无手动排序、无重排控件**：提醒的身份就是它的时刻，行间顺序无语义（各自按各自时刻触发），故不给 `SubtaskList` 的上移/下移/拖拽——比子任务更简单。行按**插入顺序**显示（不排序，避免在位改时刻时行跳动）。
- **重复时刻无害**：投递键是 `(todo_id, reminder_at)`（01），完全相同的两个时刻在投递侧自然去重；UI 不强制拦截（开发可选在提交时丢弃完全重复项，属裁量）。
- **数量上限**：契约列表字段上限 `MAX_LIST_ENTRIES=200`（`lib.rs:22`）。到顶时拒绝新增并经**单一** live region 播报一次（`announceFormAlert("warn", …, "transient")`），照 `SubtaskList.vue:169-172` 的既有形状；提醒的合理条数远小于 200，此上限只作兜底。

### 2. 状态（六项齐全）

- **默认**：每条已设提醒一行（`datetime-local` + 删除）+ 其下添加触发器/输入。创建态详情区默认收起（提醒随其余可选字段折叠，同现状）；编辑态详情区恒开。
- **悬停**：删除按钮 `hover:text-red-600 dark:hover:text-red-400`（既有）；添加触发器/输入沿用 ghost/输入既有 hover；均无新类。
- **聚焦**：所有 `datetime-local` 输入、删除按钮、添加触发器的焦点框走 `CONTROL_CLASS` 内的 `focus:ring-2 focus:ring-sky-500`（原生控件 + 内联 ring，**不走 `focus-ring` shortcut**——该 shortcut 失效缺陷已转 `外观与设置/04`，本字段与 07 同理不旁路它）。
- **加载**：无异步——提醒改动只进草稿、随原子保存落库，与 `recurrence` 同，无 loading 态。
- **空数据**：`draft.reminders` 为空 → 只显示 `＋ 添加提醒` 触发器（镜像 `SubtaskList` 空表），触发器即「下一步引导」，不留白屏（DESIGN「空状态」）。
- **错误**：提醒无**阻塞**校验（过去时刻是合法意图、非错误，仅逐行 amber note 提示「保存后会立即提醒一次」）；无法解析的输入＝空＝该行不成其为提醒，提交时丢弃（同现状单值「空 datetime = null」）。故本字段不参与容器的 `failures()`/焦点纠错路径（不需 `error`/`errorId`）。到顶上限走上一节的单次 warn 播报，非字段错误态。

### 3. 暗色 / 移动端 / 可访问性（多提醒点字段）

**暗色适配**（与浅色成对，全部既有类）：输入 `dark:bg-slate-900`；标签/次要文字 `dark:text-slate-400`；删除按钮 `dark:hover:text-red-400`；已过 note `dark:text-amber-300`。无新增色值。

**移动端适配**：字段 `col-span-full`，窄屏（<640px）单列满宽、行竖排；每个 `datetime-local` 输入 `min-h-11`、删除按钮 `min-h-11 min-w-11`（触控达标，相邻间隙 `gap-2`≥8px）；原生 `datetime-local` 在移动端给系统滚轮选择器（白拿，同现状）；无固定宽高，320px 下不越界、不横向滚动（DESIGN 硬性）。

**可访问性**：
- 字段是嵌套 `<fieldset>`+`<legend>提醒</legend>`（读屏进任一行先听到「提醒」组名，与 `range` 字段同法）。
- 每行 `datetime-local` 有稳定可访问名 `提醒时间（第 N 项）`（位置入名，避免多个同名输入）；删除按钮 `aria-label` 带可读时刻上下文 `删除提醒 <可读时间>`（照 `AttachmentList` 删除按钮把条目信息编进 label 的做法）；添加触发器 `aria-label="添加提醒"`。
- **删除后焦点接管**：删掉一行后把焦点交给滑入原位的那一行的删除按钮，删的是最后一行则交给 `＋ 添加提醒` 触发器——一字不差照 `SubtaskList.focusAfterDelete`（`SubtaskList.vue:219-228`）/`DependencyList.focusAfterRemove`，键盘用户绝不掉到 page body。
- **单一 live region**：上限播报走既有 `announceFormAlert`（页面唯一 `role="status"` 区，`App.vue:275-283`，01 建立）；逐行「已过」为静态文本、非 `aria-live`；**不新增任何第二 live region**（承 02 D3 与 07 约束）。
- 键盘全通路：行内输入、删除、添加触发器、添加输入均可 Tab 达、原生选择器键盘可操作；状态（已过）文字承载、不靠颜色单传。

### 5. 界面对数据的期望 + 契约形态推荐（交编排者裁决）

契约新形态由开发定，但界面对它有如下**硬期望**，请开发据此设计契约、编排者据此裁决形态：

**A. 每个提醒点必须能承载「墙钟 + 原始偏移」，不能只塌成 UTC 瞬间。** 这是 07 收尾裁决的结论（floating 正确性要求存墙钟 + 原偏移，塌成 UTC 已不可逆丢失原始时区）。全局开关在触发时据此二选一解释：floating＝按**当前**设备偏移把墙钟重解为绝对瞬间；absolute＝认原始偏移算出的那个绝对瞬间。UI 提供墙钟（`datetime-local` 的值）；开发在用户选定/改动时**捕获当刻设备偏移**与之一并存。floating/absolute 的**选择**是全局的（第 0 节 c），故每点只存 {墙钟, 原始偏移}、不存每点标志。

**B. 单值→列表迁移无损，且对界面无感。** 旧 `reminder_at`（绝对 UTC 瞬间）→ 列表里一条提醒。旧数据无单独存的墙钟/原偏移：开发按迁移当刻设备偏移把瞬间反解为墙钟（即 `toLocalDateTimeInput` 现在显示的那个本地时刻）并存 {该墙钟, 当刻偏移}，故编辑态打开时该条显示的时刻与迁移前**逐字不变**（第 0 节 d）。正确性边界：仅当用户「在 A 时区设的提醒、迁移正好发生在已旅行到 B 时区之后」这一并发边缘，反解出的墙钟才可能偏离原始意图——旧数据里本就没有原始偏移可考，这是无损上限，简化级可接受（同 07 对旧 absolute 数据的采信边界）。

**C. `draft.reminders` 的草稿层期望（供开发接 `TodoFields` 草稿管线）**：`createEmptyDraft()` 给 `reminders: []`；`draftFromTodo` 给 `todo.reminders ?? []`；`isSameDraft`（`TodoFields.vue:73-77`）需对 `reminders` 做**结构比较**（如 `recurrence` 那样，不能用 `===` 比数组身份，否则每次保存都读成「改过」）；`draftHasDetails`（`TodoFields.vue:125-129`）现按 `!== null && !== ""` 判，空数组 `[]` 会被误判为「有内容」而自动展开详情区——需让空 `reminders` 数组计为「无内容」（treat empty array as not-set）。这些是草稿层接线点，非契约本身，但界面语义依赖它们，请开发一并处理。

**契约形态推荐（本规格取「一组绝对时刻」）**：
- **推荐（本任务落地）**：`reminders` ＝一组「绝对时刻」提醒点，每点存 {墙钟, 原始偏移}（满足 A/B/C）。迁移无损、01/04/05/06 投递模型几乎不动（本就按绝对瞬间投递、按 `(todo_id, reminder_at)` 去重，只是从「单值」变「遍历列表」）、07 全局开关自然覆盖每点。**「截止前 N」预设留给后续任务**（理由：`dueDate` 是纯日期、缺带时刻的锚，相对子日提醒无定义——第 0 节 b）。
- **备选（若产品坚持现在就要「截止前 N」，需编排者/产品拍板）**：每个提醒点改为**带载荷枚举**——`Absolute{墙钟,偏移}` 或 `Relative{offsetMinutes, anchor}`。选此须产品先定三件事：① **锚**：`dueDate` 是纯日期，「截止前 N」的时刻从何而来？（选项：锚在该日 00:00 / 某默认提醒时刻如 09:00 / 改锚到 `startsAt` 这一带时刻字段——子日相对提醒 1小时/15分钟 只在带时刻锚下才有定义）；② **无 dueDate 时**：相对提醒无锚→建议存下但**休眠不触发**，界面标「待设置截止日」，设了 dueDate 再激活；③ **改 dueDate 时**：相对提醒**跟着重算**（这正是相对提醒的价值）。UI 侧影响：添加区从「一个 datetime-local」扩为「绝对 / 相对」二选一（相对再给「N + 天/小时/分钟」），行内展示相对提醒时把算出的绝对时刻一并显示。**注意**：带载荷枚举须同步复核 `crates/server/` 的 `patch_from_json` 未知字段路径（AGENTS.md 契约节明列此坑），比推荐方案的契约与 UI 都重，故本规格**不推荐**在简化级本任务内做，列为交编排者的取舍。
- **不可选**：纯相对（无绝对）——无法承载迁移来的绝对 `reminderAt`，直接违反验收「迁移无损」，排除。

> **交编排者裁决**：相对 vs 绝对 vs 两者是**契约形态**决定，本规格按简化级与「迁移无损」硬约束**推荐绝对时刻列表**并据此给出完整可实现规格；若编排者/产品要「截止前 N」现在就进，请在派开发前定夺备选（含上面①②③三问），因为它改契约形状与本字段的添加区 UI。本规格未把契约定死，UI 主表面（一组可增删的提醒行）在两种形态下都成立，仅添加区控件随裁决增减。
