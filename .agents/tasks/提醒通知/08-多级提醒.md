## 需求（产品）

- 目标与场景：同一任务可设多个提醒点（如截止前 1 天 / 1 小时 / 15 分钟），每个提醒点各自按时触发。
- 范围（做 / 不做）：做 契约从单值 `reminder_at` 迁移到多提醒点列表（或等价形态）+ 多提醒点的设置界面 + 各点触发；不做 时区策略（07）、不做 移动端本地通知（2.3）。
- 外部前置：01（调度底座，已完成）。与 07（时区）无强制先后——但两者都改调度/契约，注意改动交接（先落地者在实现记录写清，后者对齐）。
- 验收标准（逐条可检查）：
  - [ ] 一个任务可设多个提醒点，全部按时各自触发（含 01 的驻托盘/重启补发、04 重催/05 勿扰/06 摘要对多提醒点的既有行为不回归）。
  - [ ] 契约迁移无损：既有单值 `reminder_at` 数据升级到新形态不丢；同步双端一致；`src/bindings/` 重生成、全调用方（含 snooze 改 reminderAt、01 的 due_reminders、04/05/06 的投递键）同步。
  - [ ] 多提醒点在统一创建界面/编辑态可设可存可显（复用 02/03 的字段块形态，注意提醒此前是 03 的单值字段）。
  - [ ] `cargo test --workspace`、`pnpm run check` 通过；契约变更跑 `pnpm run types:generate` 并同步调用方。
