## 需求（产品）

- 目标与场景：同一任务可设多个提醒点（如截止前 1 天 / 1 小时 / 15 分钟），每个提醒点各自按时触发。
- 范围（做 / 不做）：做 契约从单值 `reminder_at` 迁移到多提醒点列表（或等价形态）+ 多提醒点的设置界面 + 各点触发；不做 时区策略（07）、不做 移动端本地通知（2.3）。
- 外部前置：01（调度底座，已完成）。与 07（时区）无强制先后——但两者都改调度/契约，注意改动交接（先落地者在实现记录写清，后者对齐）。
- 验收标准（逐条可检查）：
  - [ ] 一个任务可设多个提醒点，全部按时各自触发（含 01 的驻托盘/重启补发、04 重催/05 勿扰/06 摘要对多提醒点的既有行为不回归）。
  - [ ] 契约迁移无损：既有单值 `reminder_at` 数据升级到新形态不丢；同步双端一致；`src/bindings/` 重生成、全调用方（含 snooze 改 reminderAt、01 的 due_reminders、04/05/06 的投递键）同步。
  - [ ] 多提醒点在统一创建界面/编辑态可设可存可显（复用 02/03 的字段块形态，注意提醒此前是 03 的单值字段）。
  - [ ] `cargo test --workspace`、`pnpm run check` 通过；契约变更跑 `pnpm run types:generate` 并同步调用方。

### 编排者并入项（来自 提醒通知/07 收尾裁决，已裁决「转任务处理」）

**本地时刻（floating）语义 + 「本地/固定」全局选择开关**：07 论证——floating（提醒设「9:00」换时区后仍在当地 9:00 触发）必须把 `reminderAt` 从绝对 UTC 改为可承载「墙钟 + 原始偏移」的形态，而这正是本子任务的契约迁移要动的地方。因此把 floating 与本任务的 `reminder_at` 单值→列表迁移**一并设计**：新形态既要支撑多提醒点，也要能表达每个提醒点的 floating/absolute 语义（或全局策略 + 每点存墙钟）。

- UI/UX 已定（07 规格）：全局单选（默认＝本地时刻 floating），放「提醒」fieldset 末尾、单个复选框（默认关＝本地时刻），说明句静态、不弹窗；界面不显当前时区。设备真实偏移的读取 07 已实现（`chrono::Local` 每轮现读），本任务复用。
- 现状：固定时刻（absolute）＝07 保持的现状（`toInstant` 存绝对 UTC、按绝对瞬间触发）。

补充验收标准：

- [ ] 「本地时刻 / 固定时刻」策略有定义与实现：改系统时区后，本地时刻语义的提醒按新时区墙钟触发、固定时刻按原绝对时刻触发；走查记录在案（07 未能做、移交本任务）。
- [ ] 契约新形态同时支撑「多提醒点」与「floating/absolute 语义」，迁移无损，同步双端一致。
