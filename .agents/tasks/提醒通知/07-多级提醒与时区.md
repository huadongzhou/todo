# 多级提醒与时区

- 级别：简化
- 状态：设计

## 需求（产品）

- 目标与场景：跨时区提醒语义可选（本地时刻 / 固定时刻），并让 Rust 调度器读到设备真实时区偏移，收敛 04/05/06 遗留的 `ZONE_OFFSET_SECONDS=0`。

  **编排者 2026-07-24 修正**：本子任务原范围含「同一任务多提醒点」，且其「范围」称多提醒契约「已在 数据与同步/03」——经核对不成立（契约至今只有单值 `reminder_at: Option<String>`，`reminderAt`→列表的迁移当初是从 03**延期到本处**、从未做）。多提醒点是一次贯穿 01/04/05/06 投递模型的契约迁移，与时区策略是两件可分的事，已按 workflow「执行中调整拆解」拆出 **08-多级提醒**（承接契约迁移 + 多提醒点触发）。本子任务只做时区策略与真实偏移。
- 范围（做 / 不做）：做 时区策略（本地时刻 / 固定时刻语义）+ 让调度器读设备真实时区偏移（经 04 `reminder_prefs` 或等价通道喂入，替换 04/05/06 的 `ZONE_OFFSET_SECONDS=0`）+ 05 转来的补推「【逾期】」文案口径一致性；不做 多提醒点（08）、不做 移动端本地通知（2.3）。
- 验收标准（逐条可检查）：
  - [ ] 调度器按设备真实时区偏移判定逾期/到期/勿扰窗/晨间时刻，东八区等主市场准点，不再一律按 UTC。
  - [ ] 「本地时刻 / 固定时刻」策略有明确定义与实现：改系统时区后，本地时刻语义的提醒按新时区的墙钟时刻触发、固定时刻语义按原绝对时刻触发；走查记录在案。
  - [ ] 补推提醒（勿扰结束的摘要与单发）的「【逾期】」文案口径一致，与「延迟发送是否算逾期」的产品定义相符（来自 05 评审转入）。
  - [ ] `cargo test --workspace`、`pnpm run check` 通过。

### 编排者并入项（来自 提醒通知/05 评审第 1 轮，已裁决「转任务处理」）

**补推提醒的「【逾期】」文案口径**（`src-tauri/src/reminder_scheduler.rs` 的 `notification_text`/`summary_notification_text`）：05 的勿扰补推里，≥2 条摘要路径刻意去掉了「【逾期】」前缀，但恰 1 条走个别发时仍带该前缀——两路径不一致。规格建议「补推（摘要与单发）都不带该前缀（勿扰晚发是有意为之、标记会误导）」，但把它交给了本子任务与时区一并定。

本子任务读真实时区 offset 收敛逾期判定，届时请把「DND / 时区导致的延迟发送是否算逾期、补推文案摘要与单发是否一致去掉【逾期】」一次定清。

补充验收标准：

- [ ] 补推提醒（勿扰结束的摘要与单发）的「【逾期】」文案口径一致，且与「延迟发送是否算逾期」的产品定义相符。
