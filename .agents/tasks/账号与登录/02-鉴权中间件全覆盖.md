# 鉴权中间件全覆盖

- 级别：直达
- 状态：开发

## 需求（产品）

- 目标与场景：token 中间件覆盖全部 /v1/*，关闭现状 /v1/sync 无鉴权的口子；未登录本地模式不受影响。
- 范围（做 / 不做）：做 中间件与接入；不做 限流（07）。
- 验收标准（逐条可检查）：
  - [ ] /v1/* 无 token 一律 401（有测试）；登录态下同步恢复。
  - [ ] 未登录时客户端不同步、不报错阻断应用。

### 编排者并入项（来自 数据与同步/06 评审第 1 轮，已裁决「转任务处理」）

**【必办】`/v1/health` 的诊断回显泄漏用户数据**（`crates/server/src/sync_store.rs` 的 `PatchFault` → `crates/server/src/metrics.rs` → `/v1/health`）：坏行诊断把 serde 的错误文本原样带出，而该文本**包含出错的值**（可能是用户的待办标题、备注等），经**无鉴权**的 `/v1/health` 端点回显给任何请求方。

这不只是「缺鉴权」——即便加上鉴权，把用户内容放进运维诊断面本身也不对。两件事请在本子任务里一起做完：

- 把 `/v1/health` 纳入鉴权覆盖（或明确划为仅内网可达并在部署侧收口）；
- 诊断只报字段名与错误类别，**不带值**。

补充验收标准：

- [ ] `/v1/health` 的响应中不出现任何用户内容（构造一条含可识别标题的坏行验证）。
- [ ] 未携带有效凭据时无法取得 `/v1/health` 的详细统计。
