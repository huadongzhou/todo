## 需求（整体）

- 目标与场景：在实现前（对未建模块）或补齐（对已建模块）先产出全应用的高保真视觉设计稿，作为「先设计 → 下载设计图 → 按设计图复现」流程的像素参照。覆盖 TODO.md 全部 15 个模块的界面表面，桌面与移动两种形态、浅色与暗色成对。
- 范围（做 / 不做）：
  - 做：以 DESIGN.md 设计令牌为唯一事实源，用 HTML/Artifact 生成高保真视觉稿并渲染导出 PNG 到 `.agents/design/<序号-短名>/`；覆盖每屏的默认/悬停/聚焦/空/错误/加载等关键状态与浅暗两版；已有文字 UI/UX 规格的屏幕（任务管理/提醒通知等已编码模块）以其规格 + 现状代码为设计输入。
  - 不做：不改产品代码（`src/`、`src-tauri/`、`crates/`）——本母任务只产出 `.agents/design/` 下的设计稿；不做「复现」（按设计图实现代码归各功能模块的后续实现，本母任务只交付设计图）；不新增设计令牌（发现 DESIGN.md 缺口时停下报告编排者，经确认再同步 DESIGN.md，不在设计稿里私自造色）。
- 外部前置：无（DESIGN.md 已是完整令牌源）。工具前置：HTML 渲染 + 截图能力（Browser 预览 + 截图）用于导出 PNG；不依赖 Figma 建稿。
- 模块覆盖对照（15 模块 → 承接子任务）：1 任务管理→02/03；2 提醒通知→10/11；3 标签→03/07；4 四象限→03/06；5 账号与登录→12；6 数据与同步→02（同步状态/存储告警条，无独立屏）；7 视图与统计→02/04/05/08/16；8 桌面端形态→02/04/13；9 移动端形态→14；10 外观与设置→01/10；11 专注计时→09；12 发布工程→16（首启/引导/空态）；13 清单→03/07；14 AI 助手→15；15 开放与集成→16。
- 整体验收标准（逐条可检查）：
  - [ ] `.agents/design/` 下每个子任务的设计稿齐备：HTML 源 + 浅色/暗色 PNG（含移动端屏的移动版），15 个模块的界面表面全部有对应设计稿。
  - [ ] 每张设计稿的色值/字号/间距/圆角/阴影/图标均可追溯到 DESIGN.md 令牌，无自造视觉；浅暗成对、正文对比 ≥4.5:1、触控目标 ≥44px、信息不单靠颜色。
  - [ ] 关键屏覆盖多状态（默认/空/错误/加载/完成态等），不是只画一个理想态。
  - [ ] 已编码模块（任务管理/提醒通知）的设计稿与现状实现一致（作为回归基线，不引入与代码冲突的新视觉）；未建模块的设计稿可直接作为复现参照。
  - [ ] 集成评审：全屏视觉一致性对齐（同类元素跨屏一致——待办行、徽标、按钮、卡片、提示条形态统一）。
