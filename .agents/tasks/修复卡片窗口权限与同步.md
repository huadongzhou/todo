# 修复卡片窗口权限与同步

- 级别：直达
- 状态：完成

## 需求（产品）

- 目标与场景：`pnpm run tauri:dev` 下整个 Vue 前端无法挂载，导致 AGENTS.md 规定的「手动走查」验证在后续所有子任务中都做不了；同时今日卡片窗口因权限范围与同步引擎两处缺陷，在真实桌面运行时既收不到数据、又会拿空 store 去跑同步。四处缺陷同源于「卡片窗口/权限声明」，合并为一个直达任务修复。

  来源：`数据与同步/01-端侧SQLite与repository.md` 评审第 1 轮第 4 条建议与第 2 轮第 1 条建议，均已由编排者裁决「转任务处理」。

  已定位的四点（诊断结论，实现方案由开发判断）：
  1. `src-tauri/capabilities/default.json` 未声明 `core:window:allow-set-theme`，`src/lib/appearance.ts` 的 `applyTheme` 调 `getCurrentWindow().setTheme()` 抛 `window.set_theme not allowed`。
  2. `src/stores/settings.ts` 的 `bootstrap` catch 分支再次 `await applyTheme(...)`，二次抛出使兜底失效，异常穿透到 `src/main.ts` 顶层 await，`createApp().mount()` 不执行 → 白屏。
  3. `src-tauri/capabilities/default.json` 的 `"windows": ["main"]` 只覆盖标签 `main` 的窗口，今日卡片窗口标签为 `today`，于是卡片 webview 内 `listen`/`emit` 全部被拒（实测：`event.listen not allowed on window "today" … allowed on: [windows: "main"]`），卡片收不到 `today-card:todos` 事件。
  4. `src/main.ts` 的 `initSyncEngine()` / `syncNow()` 未纳入 `isTodayCardWindow()` 守卫。卡片窗口 store 恒为空，而 `sync-transport.ts` 用 WebView 原生 `fetch`（不受 capabilities 管辖）确会真同步；拉到远端变更后 `applyRemoteUpsert` 全走「未知 todo → 物化」分支（`createdAt` 被改写为 `occurredAt`、`reminderAt` 置 null）并 `persist()` 写回。目前因第 3 点权限限制写入落到 localStorage 回退而未损坏 SQLite——**第 3 点一旦修好，本条会立刻升级为真实的 SQLite 数据覆写**，故两者必须同一次改完，不得拆开。

- 范围（做 / 不做）：
  - 做：上述四点的修复；`capabilities/default.json` 按 AGENTS.md「最小权限」原则声明（不要为省事给全窗口开全部权限，卡片窗口只需它实际用到的能力）；补足必要的 Rust 侧测试或前端可验证证据。
  - 不做：任何新功能；不改今日卡片的视觉与交互；不动 `数据与同步/01` 已完成的 SQLite/repository 结构；不做 Store 迁移（属 02）与契约字段扩展（属 03）。

- 验收标准（逐条可检查）：
  - [ ] `pnpm run tauri:dev` 启动后主窗口 Vue 正常挂载，界面可见可交互（这是本任务的核心目标，必须实测并写明证据）。
  - [ ] 主题切换（跟随系统/浅色/深色）在桌面端可用且不再抛权限错误。
  - [ ] `settings` store 的 `bootstrap` 在任何单点失败下都不再向外抛，前端始终能挂载（请构造失败路径验证兜底，而不只是修好权限后「碰巧不抛」）。
  - [ ] 真实桌面运行时打开今日卡片：卡片窗口能收到 `today-card:todos` 并显示今日任务；在卡片内勾选/删除能回传主窗口生效。
  - [ ] 卡片窗口不再启动同步引擎；主窗口同步行为不变。
  - [ ] `capabilities/default.json` 的权限增量逐条可解释为「当前功能实际用到」，无冗余授权。
  - [ ] `cargo test --workspace`、`cargo check --workspace`、`pnpm run check` 通过。

### capabilities 权限增量逐条解释

`default.json`（主窗口，`"windows": ["main"]`）唯一新增 1 项：

- `core:window:allow-set-theme` —— `src/lib/appearance.ts:23` `getCurrentWindow().setTheme(nativeTheme)`。`core:default` 里的 `core:window:default` 只含只读的 `allow-theme`（getter），不含 setter，所以必须显式加。

`today-card.json`（卡片窗口，`"windows": ["today"]`，label 取自 `src/lib/today-card.ts:39` `TODAY_CARD_LABEL`）共 7 项，每项都对应实测到的 IPC 调用（下方「证据 E」为 CDP Network 抓到的完整 IPC 清单，与本表一一对应，无第 8 条）：

| 权限 | 调用点 |
|------|-------|
| `core:event:allow-listen` | `src/lib/today-card-sync.ts:117` `listen(EVENT_TODOS, …)`（卡片收今日列表） |
| `core:event:allow-emit` | 同文件 `:128` `emit(EVENT_REQUEST)` 冷启动索取、`:146` `emitToggle`、`:154` `emitRemove` |
| `core:event:allow-unlisten` | 同文件 `:136` 返回的清理函数，由 `TodayCard.vue:28` `onBeforeUnmount` 调用（已实测触发，见证据 F） |
| `core:window:allow-set-theme` | 卡片同样跑 `settings.bootstrap()` → `applyTheme()`，卡片模板有整套 `dark:` 变体，需要正确主题 |
| `store:allow-load` | `src/lib/settings-storage.ts` 各 `load(STORE_FILE, …)` |
| `store:allow-get` | 同文件 `store.get<unknown>(key)`（读 theme / closeToTray / showTodayCard） |

### 诊断复核

四点诊断经实测全部成立，无需纠正。补充两条实测澄清：

- 第 3 点的权限拒绝确实按窗口生效：修复前卡片 webview 的 `event.listen` 被拒；改成按窗口分组的两份 capability 后，卡片的 `listen`/`emit`/`unlisten` 全部放行，而主窗口权限集未被扩大。
