### 0. 组织方式与四个正面表态（编排者点名）

**组织方式 —— 平行的第三个兄弟区块 `AttachmentList.vue`，不进 `TodoFields`、不与 `SubtaskList` 合并。**

- 结论：在 `TodoItem.vue` 编辑态 `<form>` 内，**新增组件 `src/components/AttachmentList.vue`**，渲染在 `<SubtaskList>` **之后**、「Enter 保存 · Esc 取消」动作条之前，成为与 `SubtaskList` **平行的第三个兄弟区块**（顺序：`<TodoFields>` → `<SubtaskList>` → `<AttachmentList>`）。对外只收 `todo`（读 `attachments`）、对内直接调 store。
- 为什么不进 `TodoFields`：与 10（子任务）逐字同理——`TodoFields` 同时被创建界面（`App.vue`）与编辑态渲染，任何进 `TodoFields`/`FIELDS`/`TodoDraft` 的东西都会一并出现在统一创建界面。附件挂在**已存在的任务**上（含文件选择、打开等需要落库对象的操作），不属统一创建阶段，故必须在 `TodoFields` 之外。**`TodoDraft`/`TodoFields.vue`/`FIELDS` 零改动，02 验收 B2（容器不被污染）不破**：`TodoItem.vue` 编辑态只多一行 `<AttachmentList :todo="todo" />`，不因此获知任何标量字段名、列数、高度或滚动。
- 为什么不与 `SubtaskList` 合并成一个组件：两者行模型不同——子任务是「标题 + 完成态 + 排序」，附件是「kind + url + name + 打开动作（含原生文件选择/打开）」。塞进同一个组件会逼它按两套无关的数据模型分支，破坏各自形状。二者作**平行兄弟区块**：交互相似（一组可增删的行，在编辑态管理），但各自独立、各自即时落库。
- 附件写入**不进 `TodoDraft`**：草稿仍只装标量字段。附件的每次变更由 `AttachmentList` 直接调 store（复用 `applyChange` + `recordHistory` 的既有编辑路径；开发侧需为 `FieldChange` 的 `Pick` 联合补 `"attachments"` 并新增一个承载 `attachments` 数组的 edit 通道 `editAttachments(id, next)`，附 `sameAttachments` 守卫使未变更不写空 op、不记空撤销——与 10 的 `editSubtasks`/`sameSubtasks` 同构；本规格只约定交互与提交粒度，不设计 store）。它独立于父任务草稿的「Enter 保存 / Esc 取消」：附件是即时落库的离散操作，不随草稿保存/取消而提交或回滚。

**a) 链接 vs 文件的挂载入口 —— 同一「添加」区里的两个并列入口，各自的录入方式不同。**

- 结论：底部「添加」区**并列两枚 ghost 触发按钮**：`[🔗 链接]`（`Link` 图标）与 `[📎 文件]`（`Paperclip` 图标）。两者是同一入口区下的**两个并列选项**（不是一个入口 + kind 切换开关，也不是散落两处）。选并列而非「一个添加按钮 + 选类型」：链接是**文本录入**（粘贴/输入 URL），文件是**系统对话框选取**（不打字），两种录入方式差异太大，合成一个入口再切模式反而多一步、更绕。
  - **链接**：点 `链接` 就地展开一枚 URL 文本输入（`placeholder="粘贴链接…"`）+ 右侧「添加」按钮（`Plus`）；**回车或点按钮**提交，提交后**清空输入并保留焦点**，可连续录入多条（呼应 `SubtaskList` 添加框节奏）。空/纯空白 → 无操作。
  - **文件**：点 `文件` **直接唤起系统文件选择对话框**（原生能力，见 b/「开发侧原生前置」）；选定后追加一条 `kind: File` 附件（`url` = 对话框返回的路径，`name` 缺省取路径 basename，见 c）。文件路径不让用户手打，故无文本输入。单选（一次挂一个文件，简化范围；多选属后续增强，不做）。
- URL 的输入与校验（**界面层表态**；契约层校验归开发）：
  1. **长度**：去空白后按码点上限 2048（契约 `MAX_URL_CHARS`，该常量私有于 crate 未导出，故在组件内**镜像**一个 `MAX_URL = 2048` 局部常量并加注释——与 10 镜像 `MAX_SUBTASKS = 200` 同法）。输入/粘贴按码点截断，复用与标题字段一致的码点截断 + 「还可输入 n 字/已达上限」计数逻辑（仅临近上限才出计数），粘贴超长的截断经**唯一 live region** 播报。上限 200 条（`MAX_LIST_ENTRIES`，同样镜像 `MAX_ATTACHMENTS = 200`）：达上限后新增（链接或文件）不生效，经同一 live region 播报。
  2. **scheme 策略（界面层）—— 不硬限 http/https，但在界面层挡掉两种纯注入 scheme。** 理由：用户挂的是**自己的**链接（可信，见 d），`mailto:`、应用深链（如 `obsidian://`、`ftp://`）等都是正当用途，硬白名单 http/https 会误伤 power user。但 `javascript:` 与 `data:` 两种 scheme 从不是「稍后打开的链接」、且是经典注入向量，界面层**拒绝加入**（就地 inline 提示「仅支持网页或应用链接」，不落库、不触发打开）。除此之外接受任意非空 URL，契约的「非空 + ≤2048 码点」为存储底线（开发落契约层）。
  3. **粘贴便利（推荐，可选）**：提交时若输入不含 `scheme:` 前缀且形似主机（含点、无空格），可自动前缀 `https://`（用户常粘 `example.com`）。此为便利项，评审/开发认为增复杂度可去掉，不影响主结论。

**b) 「打开」的呈现与降级 —— 行的标签即打开触发；失败/非 Tauri 一律走唯一 live region 降级，不崩溃。**

- 附件行的**标签部分是一枚 `<button>`（打开触发）**，非整行可点（整行按钮内再套「移除」按钮属嵌套可交互控件，读屏/键盘皆有害）。行结构 `[kind 图标] [打开标签按钮 flex-1 truncate] [移除]`——只有标签按钮与移除按钮两个 Tab 停靠点。
- **打开语义**：
  - **链接**：在系统默认浏览器打开该 URL。
  - **文件**：用系统默认程序打开该文件。
- **运行时降级（关键，界面层表态）**：
  - **Tauri 桌面**：链接与文件都经**原生 opener 命令**打开（这样链接进用户真实默认浏览器而非内嵌 webview）。具体用哪个 opener 插件/命令、能力声明属开发（见「开发侧原生前置」）。
  - **非 Tauri（浏览器 dev / 移动端 web）**：**链接**降级为 `window.open(url, "_blank", "noopener,noreferrer")`（浏览器可开，`noopener,noreferrer` 防 opener/referrer 泄漏）；**文件**无法从浏览器沙箱打开本地路径，点击时为**「不崩溃的空操作 + 播报」**——经唯一 live region（`warn`/`transient`）播报「此环境无法打开本地文件（仅桌面应用支持）」。文件打开按钮**不做 runtime 禁用**（避免「为何变灰」的困惑），而是保留可 Tab、点击即解释——更诚实、与「降级提示不崩溃」一致。
  - **文件丢失/被移动（验收：文件丢失时降级提示不崩溃）**：UI **不预检**文件是否存在（多一次原生调用且有竞态）；而是 `await` 原生打开结果，**捕获失败**后经唯一 live region（`warn`/`transient`）播报「无法打开文件：文件可能已被移动或删除。」。绝不 `throw` 到未捕获、不白屏。
- **降级提示的通路（关键约束：不新增第二个 live region）**：上述所有降级/失败提示、以及 a) 的上限/截断，全部经 `form-alert.ts` 的 `announceFormAlert`（`source:"form"`）写入页面**唯一** `role="status"` 区（`App.vue` L371），沿用 `page-alert.ts` 优先级仲裁——**不新建 live region、不做行内报错块**。选唯一 live region 而非「行内标记」：与 10 精神一致（页面单通道），行内每行挂一个报错面是第二状态面、抬升行密度。（若日后确需，行可加一个**非仅颜色**的 transient 标记辅助，但权威播报始终是唯一 live region。）

**c) 附件行的展示 —— 显示名/回退、kind 文字+图标、窄屏截断不溢出。**

- **主标签文本**（打开按钮内可见文字）：`name?.trim()` → 若无，`File` 取 `url` 的 **basename**（按 `/` 与 `\` 双分隔取末段，Windows 对话框返回反斜杠路径），`Link` 取 `url` 本身。取 basename 而非全路径：即使长路径被截断，文件名这段仍可见。
- **kind 图标**（`DESIGN.md` 唯一图标源 `lucide-vue-next`，描边风格，16 内联档）：`Link` → `Link`（链形）；`File` → `Paperclip`（回形针，附件通用隐喻，与「链接」链形明确区分）。图标 `aria-hidden="true"`——**kind 由文字承载，不靠图标孤表**：打开按钮的可访问名含 kind 词（`打开链接 X` / `打开文件 X`），并前置 `sr-only`「链接：」/「文件：」；可选在标签尾附一枚 `ExternalLink :size=14`（`aria-hidden`）暗示「外部打开」，嫌噪可去。
- **移除控件**：行尾一枚 ghost 图标按钮（`Trash2`，`:size=20`，触控 ≥44px），`hover:text-red-600 dark:hover:text-red-400`（破坏性用红并与常规操作分离，出处 `TodoItem.vue` L489 + `DESIGN.md` 待办行/可访问性节）。即时落库、可撤销。
- **窄屏长路径**：打开按钮内文本 `truncate`（单行省略号），其容器 `min-w-0 flex-1`——`min-w-0` 是 flex 子项能收缩换省略号的前提，否则超长路径把行撑出**横向滚动**（`DESIGN.md` 禁止移动端横向滚动）。完整 `url`/路径经 `:title` 绑定在悬停显示、并入可访问名。极窄（320px）下标签 `flex-1` 收缩、kind 图标与移除按钮 `shrink-0` 不换行溢出。

**d) 安全提示（界面层）—— 打开是正常操作；展示防界面注入。**

- 用户挂的是**自己的** URL/文件（非来自不可信内容），故「打开」是用户主动的正常操作，不需二次确认弹层（与「链接来自邮件/消息需先核实」的场景不同）。
- **展示防注入**：`url`/`name` 一律经 Vue **文本插值 `{{ }}` 与属性绑定 `:title`/`:aria-label`**（二者都自动 HTML 转义），**禁止 `v-html`/`innerHTML` 构造标签**——含 `<script>`、引号、尖括号的 URL 渲染为惰性文本，无展示型 XSS。
- **双向/控制字符欺骗（推荐，可选）**：文件名/URL 里的 Unicode 双向覆写符（U+202A–U+202E、U+2066–U+2069）可让 `evil-txt.exe` 视觉伪装成 `evil-exe.txt`；C0/C1 控制符也可扰乱显示。建议在**显示前**从可见标签剥离这些码点（存储仍存原值）。低成本的显示硬化，非阻塞；嫌超范围可只做转义、后续再补。
- **打开时**：把存储的 `url` 原样作为**参数**交原生 opener（opener 插件收的是 URL/路径参数，不是 shell 字符串），不拼进任何命令行——防命令注入（属开发落地，界面层点明）。

### 1. 结构与布局

- **复用既有组件/令牌**：`Button.vue`（ghost 变体作移除/添加/两枚触发按钮）；`TodoItem.vue` 标题按钮的「裸按钮 `border-0 bg-transparent`（无 CSS reset）+ `hover:underline` + `truncate`」形态作打开标签（出处 `TodoItem.vue` L331–343）；`SubtaskList.vue` 的添加框/码点截断/唯一 live region 通道；`CONTROL_CLASS`/`LABEL_CLASS`（`TodoFields.vue` L423–425）；区块分隔线（`SubtaskList.vue` L297）。
- **新增组件**：`src/components/AttachmentList.vue`——自持附件区行结构/列数/高度/滚动；渲染位置见「组织方式」。
- **区块分隔**：`AttachmentList` 顶部用 `border-t border-slate-100 pt-4 dark:border-slate-800`（与 `SubtaskList` 区分隔线逐字一致，出处 `SubtaskList.vue` L297；`DESIGN.md` 边框 slate-200/slate-800）。它与 `SubtaskList` 上下叠放，各自一条 `border-t`，视觉上是两段并列清单区。

- **添加区**：底部并列 `[🔗 链接]` `[📎 文件]` 两枚 ghost 触发；点 `链接` 就地展开 URL 输入行（输入 + `Plus` 添加按钮），`文件` 直接唤起对话框。
- **不改**：`TodoDraft`、`TodoFields.vue`、`FIELDS`、`App.vue` 创建表单（确保附件不入统一创建界面）、`SubtaskList.vue`。
- **折叠（非编辑）行**：本规格**不新增**折叠行附件指示（产品范围仅编辑态 挂/移/开，折叠行加物件会抬升行密度、超出要求）。作为可选一致性增强，可仿子任务进度徽标加一枚中性 slate 的 `Paperclip + 计数` pill（同 `TodoItem.vue` 徽标行 `flex-wrap` 节奏），是否采纳交编排者；默认不做，决策可逆。

### 2. 状态

- **默认**：`attachments` 按数组顺序逐行显示（kind 图标 + 打开标签 + 移除）；有 ≥1 项时顶部小标签「附件 `n`」（`n` = 数量，`tabular-nums`）。底部常驻两枚触发按钮。
- **悬停**：ghost 按钮 `hover:bg-slate-100 hover:text-slate-950`（`Button.vue` 既有）；移除额外 `hover:text-red-600 dark:hover:text-red-400`；打开标签 `hover:underline` 且 `hover:text-slate-950 dark:hover:text-slate-100`（不加背景块，保持行几何，同标题按钮）。
- **聚焦**：见「应对已知缺陷」——URL 输入用显式 `focus:ring-2 focus:ring-sky-500`（`CONTROL_CLASS` 同款，已证可渲染，不依赖 `focus-ring` shortcut）；ghost/裸按钮沿用 `Button.vue`/`focus-visible` 焦点（随 外观与设置/04 修复收敛）。
- **加载**：无异步加载态——附件内嵌于已在内存的 `Todo`，增删即时渲染（无 >300ms 等待、无骨架）。**唯一的异步点是文件对话框与打开动作**：对话框由系统弹出（非页面加载态）；打开动作 `await` 原生结果，失败落 live region（见 b），不设页面 spinner。
- **空数据**：0 项时只显两枚 ghost 触发（`链接`/`文件`），不显空标签、不显空列表框（保持最小编辑器，呼应 `DESIGN.md` 空状态「给下一步引导」）。
- **错误/边界**：达 200 上限、URL 达 2048/粘贴截断、`javascript:`/`data:` 被拒、打开失败/非 Tauri 文件打开——分别经**唯一 live region**（上限/截断/打开失败）或**就地 inline 提示**（scheme 被拒，紧贴 URL 输入下方、说明修复方式，同 `TodoFields` 字段错误就近展示）处理；空白 URL 提交为静默无操作（非错误）。不弹独立报错块、不新增第二 live region。

### 4. 移动端适配

- **触控目标**：打开标签、移除、两枚触发、URL 添加按钮均补足命中区 ≥44×44px（外层 padding 撑足，不放大图标；`DESIGN.md` 触控节），相邻间隙 ≥8px。打开标签是行内主目标，`min-h-11` 保证整行可点区达标。
- **窄屏（≥320px）**：打开标签 `flex-1 min-w-0 truncate`，kind 图标与移除 `shrink-0`；长路径省略号截断、**禁止横向滚动**；极窄时添加区两枚触发可 `flex-wrap` 折行。
- **输入高度 ≥44px、`text-base`（`sm:text-sm`）** 避免 iOS 聚焦缩放（沿用 `CONTROL_CLASS`，`DESIGN.md` 表单节）。
- **文件对话框在移动端**：移动 web（非 Tauri）无文件对话框——`文件` 触发点击时同样经唯一 live region 播报降级（「此环境无法挂载本地文件」），不崩溃；移动端原生（Tauri iOS/Android）的文件选择由原生对话框处理（属开发原生前置）。
- `AttachmentList` 自身无固定高度、无内部滚动：条目多则页面变高，不造区内二级滚动（与 `SubtaskList`/`TodoFields` details 区同策）。

### 5. 可访问性

- **列表语义**：行包在 `<ul>`/`<li>`，读屏播报「列表 n 项」。区块 `<section aria-label="附件">`。
- **可访问名称**：打开标签按钮 `aria-label` = `打开${kind词} ${显示名}`（kind 词＝链接/文件，`sr-only` 前缀「链接：」/「文件：」同时可见于读屏）；移除按钮 `aria-label` = `移除${kind词} ${显示名}`；URL 输入 `aria-label="链接地址"`，添加按钮 `aria-label="添加链接"`；两枚触发 `aria-label`「添加链接」「添加文件」；kind 图标与可选 `ExternalLink` 均 `aria-hidden="true"`（kind 由文字承载，**不靠图标孤表**，`DESIGN.md` 可访问性「信息不单靠颜色/图形」）。
- **键盘全通路**：Tab 顺序＝视觉顺序（逐行：打开标签→移除；末尾：链接触发→文件触发，或展开后 URL 输入→添加）；打开标签 Enter/空格触发打开；URL 输入回车提交；移除 Enter/空格触发。所有可交互元素焦点可见（见「应对已知缺陷」）。
- **ARIA/播报**：打开失败、非 Tauri 降级、上限、截断经**唯一** `role="status"`（`aria-live="polite"`）播报（`transient`）；scheme 被拒经就近 inline 提示 + 输入 `aria-invalid`/`aria-describedby` 关联（同 `TodoFields` 字段错误模式，`TodoFields.vue` L942）。状态不孤用颜色——kind 有文字、移除是命名按钮、错误有文字。
- **焦点归还**：移除某行后焦点落相邻行的移除按钮，或无剩余项时落 `文件`/`链接` 触发（不落 `<body>`，与 `SubtaskList` `focusAfterDelete`、行内编辑器 `returnFocus` 精神一致）。
- **打开动作与文档级撤销**：编辑态下文档级 Ctrl+Z/Y 由 04 覆盖；附件的增/删各记一条撤销条目（提交粒度见「组织方式」末，一次离散动作＝一条记录）。「打开」是只读副作用、不入撤销栈。
