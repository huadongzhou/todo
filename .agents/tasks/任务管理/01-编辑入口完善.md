# 编辑入口完善

- 级别：简化

## 需求（产品）

- 目标与场景：清账既有 🚧——store 已支持改标题/截止日/提醒，补齐界面编辑入口。
- 范围（做 / 不做）：做 列表/详情内编辑入口与交互；不做 新字段（03）。
- 验收标准（逐条可检查）：
  - [ ] 列表/详情内可改标题、截止日、提醒并即时生效。
  - [ ] TODO.md 1.2 编辑 🚧 转 ✅；pnpm run check 与手动走查通过。

### 编排者并入项（来自 数据与同步/03 评审第 2 轮，已裁决「转任务处理」）

**【前置必办】出站同步 op 的标题未归一化**（`src/stores/todos.ts:169-187`）：`update` 的本地写入已过 `normalizeTitle`（按码点截到 `MAX_TITLE_CHARS`），但推给同步引擎的出站 op 仍带**未归一化**的原始 title。服务端 `SyncRequest::validate` 是整批校验，一条不合格即整批 `InvalidRequest`，且被拒的 op 不出队 —— 结果是该设备同步**永久卡死**。此路径今天不可达仅因 `update` 尚无调用方，而本子任务做的正是「给 `update` 接上编辑入口」，即由本子任务亲手让它变为可达，因此必须在接通编辑入口之前或同时修掉。

**追加（编排者，来自本任务 UI/UX 阶段的发现）**：同一段代码（`src/stores/todos.ts` 的 `update`）构造的出站 upsert patch 只带 `title` 与 `dueDate`，**漏了 `reminderAt`**——即用户改了提醒时间，另一台设备永远收不到。本任务是第一个真正让 `update` 有调用方的子任务，这个漏字段会随编辑入口上线立刻变成用户可见的同步缺陷，故一并在本任务修掉。

补充验收标准：

- [ ] 经编辑入口提交超长标题后，本地写入与出站同步 op 的 title 完全一致（均为归一化后的值）；构造一次真实同步，确认不被服务端拒、队列不卡死。
- [ ] 经编辑入口修改提醒时间后，出站 upsert patch 带上 `reminderAt`，另一端能收到该改动（须实测）。

## 规格（UI/UX）

本节只覆盖**编辑既有任务**的入口与交互，字段限定为 `title` / `dueDate` / `reminderAt` 三个既有字段。不定义创建界面（属 02）、不引入备注/开始日期/估时/时间段等新字段（属 03）、不定义撤销重做的栈与快捷键（属 04，本节只给出必须遵守的边界）。「需求」节的编排者并入项（出站同步 op 的标题未归一化，`src/stores/todos.ts:169-187`）是纯工程项，与本规格无交叉；本规格的输入框上限沿用现状 `:maxlength="MAX_TITLE_CHARS"`（App.vue:472），不额外做前端截断。

现状核对（写规格前实读）：主界面只有列表，**没有详情页**，所以「列表/详情内可改」在本任务落地为**列表行内可改**；待办行现状是 `App.vue:534-577` 的 `<article>`——完成圈按钮 + 标题 `<p>` + 到期标签 `<p>` + 删除按钮，标题当前**完全不可交互**；`src/components/ui/` 下**只有 `button/Button.vue` 一个基础组件**，没有 input / dialog / popover / date-picker 可复用。

### 0. 边界：与 02 / 03 的关系，以及「编辑与创建是否共用一个界面」的判断

**判断：共用「字段块」，不共用「容器形态」。**

- **共用的部分**：标题、截止日、提醒三个字段的控件类型、标签文案、校验规则、暗色与移动端处理，编辑态与创建界面必须完全一致——同一个字段在两处长得不一样、校验不一样，是本仓库现在最容易发生的不一致。
- **不共用的部分**：外壳。创建是「页面顶部常驻表单」（现状 `App.vue:461-517`，一次录入的动线入口），编辑是「行内展开」（贴着被改的那一行）。把两者强行统一成同一个弹层，会让创建路径凭空多一次「打开面板」的动作，直接违反 DESIGN.md 设计原则 1「内容优先、低摩擦：待办的录入与完成是核心动线」。

**留给 02 的接口（本任务只留口，不实现）**：

1. 本任务编辑态的字段块，其 DOM 结构与类串与创建表单的详情区（`App.vue:492-516`）保持**同构**——同样的 `<label><span 标签/><input/></label>`、同样的 `grid gap-* sm:grid-cols-2`。02 要抽公共组件时是机械提取，不需要重写。
2. 建议 02 把它提为 `src/components/TodoFields.vue`（props：三字段值 + 变更事件；不含提交按钮、不含容器样式），由创建界面与本任务的 `TodoItem.vue` 编辑态共同消费。**本任务不提前抽**：此刻只有一个调用方，抽象没有依据（AGENTS.md「一次性代码不抽象」）。
3. 02 若把创建界面改成弹层或整页面板，行内编辑**保持不变**：`TodoItem.vue` 只需把字段块的来源换成共用组件，触发方式与焦点归还逻辑一行都不用动。
4. 03 加字段时只往字段块里加，编辑态自动获得。若字段数增长到行内展开明显撑破列表节奏（经验阈值 5 个以上），再评估「行内展开 → 独立详情面板」，那属于新的界面形态，届时另起任务，不在本任务里预埋。

### 1. 五个必须表态的交互决定

| # | 决定 | 理由 |
|---|------|------|
| 1 | **触发＝点标题**：把标题的 `<p>` 换成 `<button>`，点击进入该行的编辑态。**不做悬停出按钮**，**不做双击**，**不做弹层** | ① 触屏没有 hover，悬停出按钮必须再补一套长按或常显方案；② 悬停才出现的控件对键盘用户等于不存在，除非再加 `focus-within` 分支，成本高于收益；③ 双击不可发现；④ 弹层要自建遮罩 + 焦点圈闭 + Esc + 移动端下滑关闭（DESIGN.md「弹层」基准），而 `src/components/ui/` 下**没有 dialog 组件**（DESIGN.md「待补充」明写 dialog 待落地），为改三个字段自建一套弹层不成比例；⑤ 标题就是编辑的主对象，点它进编辑是直接操纵，无需再教。行现状点击无任何行为，不与「点行＝完成」冲突。 |
| 2 | **行内展开**（该行原地变成表单，不是新开一层） | 保持上下文——用户能同时看到相邻任务；复用现有的详情区栅格（`App.vue:492-516`），零新增视觉模式；列表高度变化是纵向的，不引起横向滚动。 |
| 3 | **保存时机＝显式确认**：「保存」按钮提交，标题框内 Enter 等价提交；**不做失焦即存** | ① 失焦即存与 04 的 Ctrl+Z 冲突——每次失焦都产生一条用户没意识到的已提交改动，撤销栈会被无意写入塞满，「撤销一次」到底退回哪一步无法预期；② 每次失焦都会记一条出站同步 op（`stores/todos.ts:178-187`），改一个字段能推出三条 op；③ `type="date"` / `type="datetime-local"` 在原生选择器打开与关闭期间会产生 blur/change，失焦即存会把半填的日期写进库；④ 有显式保存才有干净的「取消」语义（见 #4）。 |
| 4 | **取消＝丢弃未提交草稿，不入撤销栈**；Esc 与「取消」按钮等价 | 草稿从未落库，不是数据，因此与 04 的撤销互不相干——**给 04 的硬边界：编辑态激活期间（有行处于编辑态），全局 Ctrl+Z / Ctrl+Y 必须让位给输入框自身的原生文本撤销，不得触发任务级撤销**；否则用户在输入框里想撤销一次打字，结果撤掉了上一条任务的删除。04 判断依据可以是「当前焦点在编辑态表单内」或「存在编辑中的行」，取哪个由 04 决定，但让位这件事不可协商。 |
| 5 | **空标题＝拒绝提交并说明**；纯空白字符与空等价 | store 现状 `update` 对空标题**静默不改**（`stores/todos.ts:171`），若 UI 放行，用户会看到「按了保存、标题没变、没有任何解释」。所以 UI 必须先拦：提交时若 `trim()` 为空，阻止提交、标题框下方出错误文案、焦点留在标题框。**保存按钮不设 `disabled`**——这与创建表单的「添加」按钮（`App.vue:487` 用 `:disabled`）不同，是有意为之：创建是从空开始，禁用态天然可读作「还没输入」；编辑是把已有内容清空，禁用会读作「界面卡了」，而且禁用后浏览器不会执行隐式提交，Enter 会毫无反应。 |

**日期与提醒用什么控件**：`src/components/ui/` 里没有任何输入类基础组件，因此沿用现状的原生控件——截止日 `<input type="date">`、提醒 `<input type="datetime-local">`（与 `App.vue:500-514` 同款）。DESIGN.md「表单」基准要求语义化 `type` 唤起正确键盘，原生控件同时白拿系统日期选择器与移动端原生滚轮。**不引入第三方日期选择器**：新依赖 + 新视觉语言 + 自建可访问性，为两个字段不成比例。

**清空的处理**：两个日期字段都允许清空（清空输入框后保存 → `null`）。截止日清空后行内到期标签消失；提醒清空后本地定时器由 `scheduleReminder` 开头的 `clearTimer` 自动取消（`src/lib/notifications.ts:100-102`），无需额外 UI。⚠️ 跨设备清空存在**已知契约缺口**，见第 8 节第 1 条。

**不做的校验**：不校验「提醒晚于截止日」等跨字段关系——产品未定义该规则，属 02/03 的字段语义范围。

### 2. 结构与布局

**新增组件 1 个**：`src/components/TodoItem.vue`——一行待办，同时承载展示态与编辑态。理由：行内草稿（三个 ref）与焦点归还是「一行」的私事，塞回 `App.vue`（已 590 行）会让 `v-for` 内挂上一整套表单状态。**互斥归列表**：`App.vue` 只持有 `editingId: string | null`，保证同一时刻只有一行在编辑（多行同开会让列表变成一片表单，且 Tab 顺序失控）。复用组件：`src/components/ui/button/Button.vue`（`default` 与 `ghost` 两个既有变体）。

**不改的部分**：`src/components/TodayCard.vue` **不加编辑入口**——卡片是速览面，窗口窄、没有焦点管理预算，编辑一律回主窗；主窗改完标题后卡片经既有 `today-card-sync` 推送刷新（开发核对一次 `setupTodayCardSync` 的 watch 是否覆盖标题变化即可，机制本身不改）。

**展示态**（`<article>` 的容器类串保持现状 `flex items-center gap-3 border-b border-slate-100 px-4 py-3 last:border-0 dark:border-slate-800`）：

```
<article>
  <button 完成圈>                     ← 现状不动（h-6 w-6 …… focus-ring）
  <div class="min-w-0 flex-1">
    <button                            ← 新增：标题即编辑触发器（原来是 <p>）
      class="m-0 block w-full min-h-11 rounded-md text-left text-slate-700
             hover:underline hover:text-slate-950 focus-visible:focus-ring
             dark:text-slate-200 dark:hover:text-slate-100 sm:min-h-0"
      :class="完成态 ? 'text-slate-400 line-through hover:text-slate-400
                        dark:text-slate-500 dark:hover:text-slate-500' : ''"
      :aria-label="`编辑 ${todo.title}`">
      {{ todo.title }}
    </button>
    <p 到期标签>                        ← 现状不动，保持非交互

  <Button 删除>                        ← 现状不动

```

- 标题按钮**不加水平内边距、不加负外边距**：hover 反馈用「下划线 + 文字色加深」而不是底色块，因此几何零变化——不用为了对齐再去动行的 `px-4`，也不会把与完成圈之间的 `gap-3`（12px）吃到 8px 以下（DESIGN.md「相邻可点目标间隙 ≥ 8px」）。`button, input { font: inherit }` 已在 `src/styles/main.css` 生效，字号自动继承 16px 正文，无需显式 `text-base`。
- **到期标签保持非交互**：它是状态展示，做成控件会把「有颜色＝可点」的心智扩散到别处；且它与标题按钮只隔 `mt-1`（4px），两个相邻可点目标必然互相误触。
- 完成态同样可编辑（store 不区分），标题按钮在完成态保留删除线与低对比文字色，hover 只加下划线、**不改文字色**——加深会让完成项看起来像回到未完成。

**编辑态**（同一 `<article>`，容器改为块级：`border-b border-slate-100 px-4 py-3 last:border-0 dark:border-slate-800`，去掉 `flex items-center gap-3`）：完成圈与删除按钮**在编辑态隐藏**——破坏性操作不与编辑并存（DESIGN.md「待办行」基准：破坏性操作与常规操作在视觉上分离），同时让 Tab 顺序只剩表单本身。

```
<form class="grid gap-3" :aria-label="`编辑 ${进入编辑时的标题}`"
      @submit.prevent="save" @keydown.esc="cancel">

  <label class="block">
    <span class="mb-1 block text-xs font-medium text-slate-500 dark:text-slate-400">标题</span>

      :aria-describedby="titleError ? `todo-title-error-${todo.id}` : undefined" />

  <p v-if="titleError" :id="`todo-title-error-${todo.id}`"
     class="m-0 text-xs text-red-600 dark:text-red-400">
    标题不能为空，请输入内容，或按 Esc 取消编辑。
  </p>

  <div class="grid gap-3 sm:grid-cols-2">     ← 与创建表单详情区同构（App.vue:492-516）
    <label class="block">
      <span class="mb-1 block text-xs font-medium text-slate-500 dark:text-slate-400">截止日</span>
      <input v-model="draftDueDate" type="date" class="[同上输入类串]" />
    </label>
    <label class="block">
      <span class="mb-1 block text-xs font-medium text-slate-500 dark:text-slate-400">提醒时间</span>
      <input v-model="draftReminderAt" type="datetime-local" class="[同上输入类串]" />
    </label>
  </div>
  <p v-if="reminderInPast" class="m-0 text-xs text-amber-700 dark:text-amber-300">
    提醒时间已过，保存后会立即提醒一次。
  </p>

  <div class="flex flex-wrap items-center justify-between gap-3">
    <p class="m-0 text-xs text-slate-500 dark:text-slate-400">Enter 保存 · Esc 取消</p>
    <div class="flex gap-2">
      <Button variant="ghost" class="min-h-11" @click="cancel">取消</Button>
      <Button type="submit" class="min-h-11">保存</Button>
    </div>
  </div>
</form>
```

- **预填与回写**：三个输入在进入编辑态时用当前值预填。截止日与存储格式同为 `YYYY-MM-DD`，直填；**提醒需要换算**——存储是 ISO 瞬时（UTC），`datetime-local` 要的是本地 `YYYY-MM-DDTHH:mm`，即 `App.vue:222-226` `toInstant()` 的逆函数，仓库现在**没有**这个函数，由开发新增并与 `toInstant` 放在一处。缺了它编辑态会显示空提醒，用户一保存就把已有提醒清掉。
- **未改动不提交**：保存时若三个字段与进入编辑时完全相同，直接关闭编辑态、**不调用 `store.update`**——否则会凭空产生一条出站同步 op，并（在 04 落地后）往撤销栈里塞一条什么都没改的记录。
- **不做 click-outside 自动关闭**：点空白处关闭会静默丢草稿。编辑态只由 保存 / 取消 / Esc 结束。
- **切到另一行＝对当前行执行「取消」**（草稿丢弃，不弹确认）。理由：编辑面只有三个字段，重做成本极低；弹确认需要仓库尚不存在的 dialog 组件与焦点圈闭，成本远高于收益；用户点另一行的标题按钮是明确动作，不是误触（触发器是按钮点击，不是悬停，也没有 click-outside）。

### 5. 移动端适配

- **触控目标**：标题按钮 `min-h-11`（44px）作为**基础值**、`sm:min-h-0` 在桌面回落（移动优先，指针设备不需要 44px 撑高行）；三个输入 `min-h-11`（DESIGN.md「表单」基准：移动端输入高度 ≥ 44px）；保存/取消按钮 `min-h-11`。相邻间隙：标题按钮与完成圈 `gap-3`（12px）、与删除按钮 `gap-3`、两个按钮之间 `gap-2`（8px），均 ≥ 8px。

- **窄屏行为**：字段区 `grid gap-3` 单列起步，`sm:grid-cols-2`（640px 起）截止日与提醒并排——与创建表单的断点一致，不新增断点。按钮行 `flex-wrap`，320px 下「Enter 保存 · Esc 取消」提示与按钮组自动换行（提示在上、按钮在下），**不出现横向滚动**（DESIGN.md 硬性）。所有输入 `w-full`，无固定宽高。

### 6. 可访问性

- **可访问名称**：标题按钮 `aria-label="编辑 {title}"`——可见文字（标题）被完整包含在可访问名内，满足 WCAG「Label in Name」，与现状删除按钮的 `` `删除 ${todo.title}` ``（`App.vue:572`）同款措辞。编辑表单 `<form :aria-label="`编辑 {进入编辑时的标题}`">` 给出分组名（保存后名字不跟着变，避免读屏在焦点还在表单里时名称突变）。
- **可见标签**：三个输入全部用 `<label>` 包裹 + 可见 `<span>` 文案（标题 / 截止日 / 提醒时间），满足 AGENTS.md HTML 规范与 DESIGN.md「表单」基准。注意编辑态的标题**有可见标签**，比创建表单现状（只有 `aria-label`，`App.vue:475`）更严；创建表单的对齐留给 02，本任务不动它。
- **键盘全通路**：Tab 到标题按钮 → Enter/Space 进入编辑 → 焦点自动进标题输入框 → Tab 依次经过 标题 → 截止日 → 提醒 → 取消 → 保存（DOM 顺序＝视觉顺序）→ Enter 提交（隐式提交，保存按钮未禁用故可用）→ Esc 取消。Esc 监听挂在 `<form>` 上（`@keydown.esc`），不挂 `document`，避免与全局快捷键（`src/lib/shortcuts.ts`）抢事件。
- **焦点归还**：保存成功、取消、Esc 三条路径都把焦点**显式还给该行的标题按钮**（`nextTick` 后取 ref）。这条是硬要求——编辑态是展开层，DESIGN.md 可访问性基准要求「关闭后归还焦点」；不归还的话焦点掉到 `<body>`，键盘用户要从页头重新 Tab。保存后按钮的可访问名会变成「编辑 {新标题}」，读屏在获得焦点时读出新名，**这本身就是结果播报**，因此不新增 live region。
- **不新增 live region**：页面已有唯一的 `role="status" aria-live="polite"` 提示条（`App.vue:283-291`），写入失败经它播报；同页两个 live region 会互相打断。
- **校验的可访问性**：错误文案节点 id 为 `todo-title-error-{id}`（列表内必须按 id 唯一），经 `aria-describedby` 关联，同时 `aria-invalid="true"`；错误文案给出修复方式（「请输入内容，或按 Esc 取消编辑」），不是干巴巴的「无效」。
- **不靠颜色单传**：校验错误、提醒已过均由文字直接说明；到期标签现状已带文字。
- **对比度**：新增取值全部落在 DESIGN.md 已验证的 slate/red/amber 阶内。`default` 按钮（保存）白字压 sky-500 的对比度偏差是 DESIGN.md「已知偏差」条目下的**全局待决问题**，与本任务同源不同责，本任务不单独处理。

### 两条前置必办的修复与实测

`src/stores/todos.ts` 的 `update` 原先把**原始 patch** 交给 `buildUpsertOperation`。改为先算出「实际写进本地的值」，再用它构造出站 op（`outbound: TodoPatch` 逐字段填充），同时补上漏掉的 `reminderAt`。

实测环境：`cargo run -p todo-server`（`DATABASE_PATH`/`BACKUP_DIR` 指向临时目录，`CORS_ORIGIN=http://localhost:1420`）+ `pnpm run tauri:dev`（WebView2 开 `--remote-debugging-port`，经 CDP 注入真实键盘/输入事件走查）。

1. **标题归一化**（服务端整批校验会卡死队列）：
   - 先验证失效模式真实存在——直接向 `/v1/sync` 提交一批含 501 字符标题（或纯空白标题）的 op，服务端返回 `400 {"error":"a title must contain 1 to 500 non-whitespace characters"}`，**同批次里合法的那条也没落库**（另一设备 cursor=0 拉取为空）；客户端 `syncNow` 只从 `acknowledgedOperationIds` 出队，被拒的 op 会永久留在 `pending`。
   - 修复后经编辑入口提交标题 `"  走查任务A 已改  "`（前后带空格）：本地写入 `走查任务A 已改`，服务端收到的 op patch 为 `{"title":"走查任务A 已改","dueDate":"2026-07-24","reminderAt":"2026-12-31T01:30:00.000Z"}` —— 与本地完全一致。整轮走查共产生 12 条 op，应用日志每次 `Sync completed ... pending:0`，无一次 `Sync failed`，队列未卡死。
2. **`reminderAt` 出站**：同一条 op 已带 `reminderAt`（本地 `2026-12-31T08:30` → `2026-12-31T01:30:00.000Z`，UTC+7 换算正确）。反向再验一次：以另一设备身份推送 `{"reminderAt":"2027-03-05T02:15:00.000Z"}`，主窗「立即同步」后重开编辑态，提醒框显示 `2027-03-05T09:15` —— 两端双向都通。

1. 规格给标题按钮的类串未含 `border-0 bg-transparent p-0`。本仓库**没有引入任何 CSS reset**（`src/main.ts` 只 import `virtual:uno.css` + `main.css`，`main.css` 只统一了 `font` 与 `cursor`），实测裸 `<button>` 计算样式为 `background: rgb(240,240,240)`、`border: 2px outset`、`padding: 1px 6px` —— 标题会渲染成灰色按钮块并相对下方到期标签左缩 6px，与规格「hover 反馈不做底色块、几何零变化」直接冲突。补这三个既有 Uno 工具类（`border-0 bg-transparent` 见 App.vue:473，`p-0` 见 App.vue 的 fieldset）后计算样式为 `transparent / 0px / 0px`，观感与原 `<p>` 一致。**未新增设计令牌。**

### 走查结论（逐条）

- 触发与形态：标题为 `<button aria-label="编辑 {title}"`，点击行内展开；编辑态隐藏完成圈与删除按钮；表单 `aria-label="编辑 {进入编辑时的标题}"`；字段顺序即 Tab 顺序（标题 → 截止日 → 提醒 → 取消 → 保存）。
- 焦点：进入编辑焦点落标题框且光标在末尾（`selectionStart=selectionEnd=length`，非全选）；保存 / 取消 / Esc 三条路径焦点均归还该行标题按钮（保存后可访问名已变为「编辑 {新标题}」）。
- 校验：空标题与纯空白标题按 Enter 或点保存均被拒，`aria-invalid="true"` + `aria-describedby="todo-title-error-{id}"` + 文案「标题不能为空，请输入内容，或按 Esc 取消编辑。」，焦点留在标题框；保存按钮**始终未 disabled**；重新输入后错误立即消失。
- 草稿：取消 / Esc / 切到另一行都丢弃草稿（重开为存储值）；切到另一行时不抢焦点。
- 未改动不提交：开编辑态直接点保存，服务端 op 数保持不变（cursor 停在 3）。
- 提醒已过：选 2020-01-01 出 amber 提示且不阻止保存；改为未来时间提示消失。
- 完成态：完成的任务同样可编辑，标题保留删除线与 slate-400。
- 提示条：页面仍只有既有的那一处 `role="status"`，未新增第二个 live region。
- 今日卡片：`TodayCard.vue` 未加编辑入口；`setupTodayCardSync` 的 `watch(() => store.items, …, { deep: true })` 覆盖标题变化——实测开卡片窗口后在主窗改标题，卡片行文案同步变为新标题，机制未改。
- 响应式与暗色：375 / 900 宽下 `documentElement.scrollWidth === clientWidth`（无横向滚动）；375 下标题按钮 `min-height: 44px`、桌面 `sm:min-h-0` 回落为 0；暗色下标签、输入底（slate-900）、文字均按规格第 4 节成对生效（`取消` 按钮无暗色分支属 Button.vue 现状，规格已声明）。
