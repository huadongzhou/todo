## 需求（产品）

- 目标与场景：用户能在统一创建界面与行内编辑里设置一条周期规则（每日 / 每周 / 每月 / 自定义间隔 / 指定星期几 / 月末 / 工作日），并看懂自己设的是什么。引擎（`crates/domain/src/recurrence.rs` 的 `next_occurrence`）与契约（`RecurrenceRule` 等）已由 06 与 数据与同步/03 就绪，本子任务只做界面与交互。
- 范围（做 / 不做）：
  - 做：周期字段进 `src/components/TodoFields.vue` 的声明式字段表；规则的可读回显；`until` 与 `count` 的二选一收敛（见下）。
  - 不做：引擎本身（06）；实例生成与列表上的周期标识、下次到期（08）；农历与调休（07）；打卡视图（09）。
- 外部前置：无。内部依赖：06（引擎，已完成）、02（字段块与容器，已完成）。

### 编排者并入项（来自 06 评审第 1 轮，已裁决「转任务处理」）

**`until` + `count` 并存时引擎与导出文件不一致**：契约把 `until` 与 `count` 都写成停止条件且 `validate()` 不拒绝并存，于是引擎按「先到者停」；而 RFC 5545 3.3.10 明令 `UNTIL` 与 `COUNT` 不得同现，`数据与同步/08` 已裁定导出时只写 `UNTIL`。同一条规则因此可能在应用内与导出到日历后表现不同。

评审指出收敛点在「界面二选一」或「契约 `validate` 加约束」，编排者选前者——后者涉及同步兼容性评估，代价大得多。请在规则表单里把「按结束日期停」与「按次数停」做成**互斥选项**，使并存状态在界面上不可达。

- 验收标准（逐条可检查）：
  - [ ] 七类规则（每日 / 每周 / 每月 / 自定义间隔 / 指定星期几 / 月末 / 工作日）均可在创建与编辑两处设置，设完能存下、重开能读回。
  - [ ] 界面上无法同时设置「结束日期」与「重复次数」，二者互斥。
  - [ ] 设完的规则有可读回显（用户能一眼看懂自己设的是什么），文案与引擎的实际行为一致。
  - [ ] 沿用 02 的容器禁止清单：新增字段后 `App.vue` 与 `TodoItem.vue` 无需改动。
  - [ ] `pnpm run check` 通过；`cargo test --workspace` 通过。

### 编排者并入项（来自 07 评审第 1 轮，已裁决「转任务处理」）

**闰月生日的产品取舍**：农历周期若锚在「范围内不再复现的位置」（如 1984 闰十月、2014 闰九月、2033 闰十一月，或闰月的三十日），该规则在后续年份可能永远不再发生。评审在 72,000 个逐日锚点中找到 267 个这样的位置。

引擎侧的语义（此类情形应与公历同形返回「没有下一次」而非报越界）已由 07 处理；**但「用户设了一个永远不会再来的日子该怎么办」是界面问题**：要不要在选择器里允许选闰月？选了不复现的年份怎么提示？是否提供「顺延到下个月同日」之类的降级选项？请在本子任务设计规则表单时一并定清并写进规格。

补充验收标准：

- [ ] 用户设置农历周期时，选到「不再复现的位置」有明确且可理解的处理（禁止选择、或选后明确告知后果），不会出现「设了但永远不触发且无任何提示」。
