## 需求（产品）

- 目标与场景：用户能在统一创建界面与行内编辑里设置一条周期规则（每日 / 每周 / 每月 / 自定义间隔 / 指定星期几 / 月末 / 工作日），并看懂自己设的是什么。引擎（`crates/domain/src/recurrence.rs` 的 `next_occurrence`）与契约（`RecurrenceRule` 等）已由 06 与 数据与同步/03 就绪，本子任务只做界面与交互。
- 范围（做 / 不做）：
  - 做：周期字段进 `src/components/TodoFields.vue` 的声明式字段表；规则的可读回显；`until` 与 `count` 的二选一收敛（见下）。
  - 不做：引擎本身（06）；实例生成与列表上的周期标识、下次到期（08）；农历与调休（07）；打卡视图（09）。
- 外部前置：无。内部依赖：06（引擎，已完成）、02（字段块与容器，已完成）。

### 编排者并入项（来自 06 评审第 1 轮，已裁决「转任务处理」）

**`until` + `count` 并存时引擎与导出文件不一致**：契约把 `until` 与 `count` 都写成停止条件且 `validate()` 不拒绝并存，于是引擎按「先到者停」；而 RFC 5545 3.3.10 明令 `UNTIL` 与 `COUNT` 不得同现，`数据与同步/08` 已裁定导出时只写 `UNTIL`。同一条规则因此可能在应用内与导出到日历后表现不同。

评审指出收敛点在「界面二选一」或「契约 `validate` 加约束」，编排者选前者——后者涉及同步兼容性评估，代价大得多。请在规则表单里把「按结束日期停」与「按次数停」做成**互斥选项**，使并存状态在界面上不可达。

- 验收标准（逐条可检查）：
  - [ ] 七类规则（每日 / 每周 / 每月 / 自定义间隔 / 指定星期几 / 月末 / 工作日）均可在创建与编辑两处设置，设完能存下、重开能读回。
  - [ ] 界面上无法同时设置「结束日期」与「重复次数」，二者互斥。
  - [ ] 设完的规则有可读回显（用户能一眼看懂自己设的是什么），文案与引擎的实际行为一致。
  - [ ] 沿用 02 的容器禁止清单：新增字段后 `App.vue` 与 `TodoItem.vue` 无需改动。
  - [ ] `pnpm run check` 通过；`cargo test --workspace` 通过。

### 编排者并入项（来自 07 评审第 1 轮，已裁决「转任务处理」）

**闰月生日的产品取舍**：农历周期若锚在「范围内不再复现的位置」（如 1984 闰十月、2014 闰九月、2033 闰十一月，或闰月的三十日），该规则在后续年份可能永远不再发生。评审在 72,000 个逐日锚点中找到 267 个这样的位置。

引擎侧的语义（此类情形应与公历同形返回「没有下一次」而非报越界）已由 07 处理；**但「用户设了一个永远不会再来的日子该怎么办」是界面问题**：要不要在选择器里允许选闰月？选了不复现的年份怎么提示？是否提供「顺延到下个月同日」之类的降级选项？请在本子任务设计规则表单时一并定清并写进规格。

补充验收标准：

- [ ] 用户设置农历周期时，选到「不再复现的位置」有明确且可理解的处理（禁止选择、或选后明确告知后果），不会出现「设了但永远不触发且无任何提示」。

## 规格（UI/UX）

### 0. 架构判断：进字段表的新 `control` 分支，而非兄弟区块

**结论：周期是 `TodoFields.vue` 声明式字段表里的一行（`FIELDS` 新增一条 `key: "recurrence"`），`control` 联合新增一个 `recurrence` 分支；该分支不走字符串 `FieldCodec`，而是委托给新建子组件 `RecurrenceField.vue`，直接读写 `draft.recurrence: RecurrenceRule | null`。不采用子任务/附件/依赖那样的兄弟区块。**

依据（实地核对形状后）：

- **它必须出现在创建界面**。子任务（`SubtaskList`）、附件（`AttachmentList`）、依赖（`DependencyList`）在 `TodoItem.vue` 里是 `<TodoFields>` 的**兄弟**，且刻意不进创建表单——因为它们「属于已存在的任务」，并且**直接提交给 store**（不经 draft）。周期相反：README 创建字段集含周期，且它必须随 `draft` 走创建/编辑两条提交路（`App.vue.submit` → `todoStore.add`，`TodoItem.save` → `todoStore.update`）。兄弟区块两个特性都不满足，直接排除。
- **字段表本就为「新形状」预留了扩展点**。`FieldControl` 联合上方注释明说「A new field is a row in FIELDS；a new shape is one more variant here and one more branch in the template」，并已列出 `select`/`checkbox` 作为已知下一形状；`range` 已是「一字段两控件、不走单一 codec」的先例（`parts` + 每半一个 `onInput`）。周期是「一字段多控件」的更复杂先例，正是这个扩展点的目标用法。
- **复合性靠下沉子组件消化，不靠膨胀 codec**。`FieldCodec` 是字符串进出（`read: draft=>string` / `write: (draft,raw:string)=>draft`），装不下 `RecurrenceRule` 复合对象；且闰月警告要异步问引擎（见 §3c），`FieldDefinition.note` 是同步纯函数，也装不下。因此 `recurrence` 分支不复用 codec，模板分支只渲染 `<RecurrenceField v-model="draft.recurrence" :anchor="draft.dueDate">`，全部复合状态与异步回显封装在子组件内。

**对容器边界 / 02 B2 的影响：零污染达标。**

- `App.vue`、`TodoItem.vue` **不改**（满足验收「新增字段后 `App.vue` 与 `TodoItem.vue` 无需改动」）。两者只知道「有一个字段块」，从不点名字段。
- 改动只落在字段块自身 `TodoFields.vue`（新增一行 `FIELDS` + 一个 `kind` 分支）与新建的 `RecurrenceField.vue`。模板仍「只按 `kind` 分支、不按字段名分支」，与 02 的声明式约定一致；字段块不得因此获得自己的固定高度/滚动——`RecurrenceField` 随内容把页面撑高即可，**禁止**自带 `overflow`/固定 `height`（沿用 details 区「more fields make the page taller, they do not make this scroll」）。
- `span: "full"`（复合控件占整行，理由同 `range`），`group: "time"`（它回答「多久/何时重复」，落在既有四组的「时间」，不新开第五组）。建议 `FIELDS` 里紧跟 `dueDate` 之后排列——周期以截止日为锚点（见 §3c），相邻放置让「无截止日」警告有上下文。

**TodoFields.vue 需要动的接线点（供开发核对，均在字段块内部，不外溢容器）：**

1. `TodoDraft` 增加 `recurrence: RecurrenceRule | null`；`createEmptyDraft` 补 `recurrence: null`；`draftFromTodo` 补 `recurrence: todo.recurrence ?? null`。
2. `isSameDraft` 目前逐键 `===`，对象按引用比较会恒判「已改」——`recurrence` 键需改为结构相等比较（`JSON.stringify` 或字段级比较）。**这是本次唯一会破坏既有函数语义的点，必须处理**，否则「改了什么都没改也写一条空操作/空 undo」的既有保证在周期字段上失效。
3. `keysOf`：`kind === "recurrence"` 时返回 `["recurrence"]`（当前只处理 `range`/单 codec，缺此分支会取 `control.codec.key` 崩溃）。
4. `visibleGroups`：`single = kind==="range" ? null : control.codec` 对 `recurrence`（无 codec）会 `undefined.read` 崩溃——需为 `recurrence` 增分支，产出交给子组件的绑定而非字符串 `value`/`onInput`。
5. 新增 `onRecurrenceChange(rule: RecurrenceRule | null)`：走 `commitDraft({ ...pendingDraft, recurrence: rule })` + `clearRejectionIfTouched()`，与 `onFieldInput` 同构，保证「一 tick 内两字段各自写」的既有安全（`pendingDraft`）。
6. 阻塞校验（间隔/次数越界，见 §3-错误）：`recurrence` 这行给同步 `error?(draft)`，让 `failures()`/`validate()` 能拦截并聚焦；子组件用 `registerControl` 把首个可聚焦控件（频率 `<select>`）登记在字段 id 下，供聚焦。
7. store 侧（开发范围，非本组件）：`NewTodoInput`/`TodoEdit` 增 `recurrence`；`add` 把 `recurrence` 写进新任务并**带进出站 upsert 操作**（当前 `add` 的 upsert 未含 recurrence，漏写会导致跨设备看不到周期）；`update` 已有 `patch.recurrence` 通路（`todos.ts:1442/1473`），确认 `TodoEdit` 放行即可。

### 1. 结构与布局

新建 `src/components/RecurrenceField.vue`，`props: { modelValue: RecurrenceRule | null; anchor: string | null }`，`emit: update:modelValue`。整体是一个 `<fieldset class="m-0 border-0 p-0">` + `<legend>重复</legend>`（`legend` 用 `LABEL_CLASS`，与 `range` 的嵌套 fieldset 同构，让读屏进入任一子控件先听到「重复」）。

**渐进式显示矩阵（要点 a：最少控件表达七类规则，选谁只显示谁的从属项）：**

| 频率（`<select>` 顶层控件） | 附加显示的子控件 | 覆盖的「七类」 |
|---|---|---|
| 不重复（`recurrence=null`，默认/空态） | 无 | — |
| 每日 | 间隔 | 每日；自定义间隔 |
| 每周 | 间隔 + **星期集合**（7 枚 chip） | 每周；指定星期几；自定义间隔 |
| 每月 | 间隔 + **农历**开关 + **月内位置**（同一日/指定某日[数字]/最后一天） | 每月；月末；自定义间隔 |
| 每年 | 间隔 + **农历**开关 | （每年）；自定义间隔 |
| 工作日 | 间隔（单位＝个工作日） | 工作日；自定义间隔 |
| （以上任一非「不重复」） | **结束条件**（3 选 1 单选，见 §3b）+ 回显行 + 警告位 | — |

说明：
- 「频率」用原生 `<select>`（`FieldControl` 注释已把 `select` 列为既定下一形状），选项：不重复 / 每日 / 每周 / 每月 / 每年 / 工作日。选「不重复」即把整条 `recurrence` 置 `null`，所有子控件收起——这是空态。
- 「自定义间隔」不是独立频率，就是**间隔数字框**（`每 [1] 天/周/个月/年/个工作日`，单位随频率变，默认 1）。一个数字框吃下「每 N」，避免多出一个「自定义」入口。
- 「农历」是与频率正交的开关，但**只对每月/每年有意义**（引擎对农历的每日/每周与公历同解），故仅在每月/每年显示；勾选写 `calendar="lunar"`，否则 `"gregorian"`。工作日不显示农历。
- 「月内位置」用 `<select>`（同一日 / 指定某日 / 每月最后一天）：选「指定某日」才显出 1–31（农历 1–30）数字框。三态恰好互斥映射契约 `month_day=None｜Some(n)｜(on_last_day=true)`——契约 `validate` 禁止 `month_day` 与 `on_last_day` 并存，这里做成单选后**该非法态在界面上不可达**。
- 「星期集合」：`每周` 才显示，7 枚 toggle chip（一二三四五六日，周一起，对齐 `Weekday` 枚举与引擎周一为首）。可全不选＝空集合＝引擎按「与截止日同一星期」，故不强制选择。

复用的既有件：`Button.vue`（`ghost` 变体，用于结束条件里可能的清除等，若需要）；数字/日期/`<select>` 输入一律复用 `TodoFields` 的 `CONTROL_CLASS`（`min-h-11 w-full rounded-lg border-0 bg-slate-100 px-3 py-2 text-base focus:ring-2 focus:ring-sky-500 sm:text-sm dark:bg-slate-900`）与 `LABEL_CLASS`（`text-xs font-medium text-slate-500 dark:text-slate-400`）；这两个常量当前是 `TodoFields.vue` 私有，建议开发提到可共享处或在子组件按同串复制（值一致即可，勿另立体系）。

回显（要点 d）：在 `src/lib/recurrence.ts` **新增** `recurrenceSummary(rule): string`（纯文本，与既有 `recurrenceLabel` 同规矩——**不写任何颜色/`dark:` 类串**，因 UnoCSS 不扫 `.ts`）。它复用 `recurrenceLabel` 取频率段，再拼星期集合（`每周一、三、五`）、月内位置（`每月 15 日`／`每月最后一天`）、结束条件（`，共 10 次`／`，截止 2026-12-31`）。`recurrenceLabel` 保持不动（其 doc 明确它只供列表 pill 的频率段），折叠行 08 已有的 `Repeat` pill 继续用 `recurrenceLabel` 不变；`recurrenceSummary` 只用于编辑器内联回显。

- 字段整体：`fieldset` 内用 `grid gap-3`。每个子控件一格：`label`（`LABEL_CLASS`）在上、控件在下，与 `range` 的 `parts` 一致。

- 星期 chip（toggle button）：

### 3. 状态（默认／悬停／聚焦／加载／空／错误）＋ 并入项 b/c ＋ 回显 d

- **默认／空态**：频率＝不重复，只剩一个 `<select>`，`recurrence=null`。无回显、无警告。任务无周期时字段就是一行下拉，不铺开无关字段。
- **悬停**：见 §2（chip/ radio 行 hover 底色位移；`<select>`/输入用原生 hover）。仅动色/透明度，遵 DESIGN 动效克制。
- **聚焦**：所有控件聚焦可见。原生输入/`<select>` 用 `CONTROL_CLASS` 自带的 `focus:ring-2 focus:ring-sky-500`（字面量，非 `focus-ring` shortcut）；chip 与 radio 用字面量 `focus-visible:ring-2 focus-visible:ring-sky-500 focus-visible:ring-offset-2 focus-visible:ring-offset-white dark:focus-visible:ring-offset-slate-950`。**刻意不用 `focus-ring` shortcut**——已知缺陷（外观与设置/04）该 shortcut 失效，字面量 ring 工具类可绕开（与 `CONTROL_CLASS` 既有写法一致）。禁止移除焦点样式。
- **加载**：闰月/不复现警告要异步问引擎（Tauri IPC），但很快，**不设独立 loading 态**：警告算出来再出现即可。非 Tauri 运行时（浏览器开发）无引擎，警告直接不显示（降级，与 `nextOccurrence`/`habitProgress` 一致）。
- **错误（阻塞提交，同步，走字段表 `error(draft)`）**：
  - 间隔非 `1..=999` 整数（含选了频率却清空间隔）：`重复间隔请填写 1 到 999 之间的整数。`
  - 结束＝「重复 N 次」但 N 非 `≥1` 整数：`重复次数请填写大于 0 的整数。`
  - 这两条对齐契约 `RecurrenceRule::validate`（interval `1..=MAX_RECURRENCE_INTERVAL=999`、`count!=0`），与 `estimateError` 同构，红字贴控件下方并说明修法。其余非法组合（星期重复、`month_day`+`on_last_day` 并存）已被控件形态挡在不可达，无需红字。

**并入项 b —— `until`＋`count` 二选一收敛：**
结束条件做成**单选（radio group）三态**：`永不`（`until=null,count=null`，默认）／`到某天停止`（显 `date` 框，写 `until`，清 `count`）／`重复 N 次后停止`（显数字框，写 `count`，清 `until`）。切换任一态即清空另一态的字段。因是一个单选组，**「两者并存」在界面上结构性不可达**，从根上消除引擎与 `.ics` 导出（08 只写 `UNTIL`）不一致的入口。满足验收「界面上无法同时设置结束日期与重复次数，二者互斥」。

**并入项 c —— 闰月/永不复现位置的处理（选后明确告知，非禁止选择）：**
采「选后告知后果」而非「禁止选择」，理由：不复现与否取决于**锚点（截止日）＋规则**的组合，而非单独某个可预枚举的选项（用户在本界面并不直接点「闰二月十五」，而是选「农历＋每年」，由截止日决定它是否落在闰月/短月位置）；逐一预禁需按每个可能锚点跑引擎，且锚点可独立变化，代价大且脆。做法：

- `RecurrenceField` 在「频率∈{每月,每年}、有截止日（锚点）、且处于 Tauri」时，用**去掉结束条件**的探针规则 `{...rule, until:null, count:null}` 调 `nextOccurrence(probe, anchor, anchor)`；若返回 `null` ⇒ 该位置在可预见年份内不再复现 ⇒ 显琥珀警告：`此重复位置在可预见的年份内不会再出现，保存后只会发生这一次。`（引擎语义由 07 保证：闰月/短月 30 日、公历 2 月 31 日等此类锚点返回「没有下一次」。）此一套机制同时覆盖农历闰月、农历短月 30 日、公历不可能日期三种情形。满足补充验收「选到不再复现的位置有明确且可理解的处理，不会出现『设了但永远不触发且无任何提示』」。
- **附带缺口（一并处理）**：周期以截止日为锚点（store `advanceRecurrences` 用 `todo.dueDate`；无截止日则永不生成下一次）。故「频率≠不重复 且 `anchor==null`」时显琥珀警告：`重复需要截止日作为起点：先设置截止日，这条重复才会生成下一次。` 同步、无需引擎。二者均为**非阻塞 note**（与 reminder「已过」note 同性质：规则本身可存、可后补截止日），若编排者倾向更强约束可升级为阻塞，但建议保持 note。

**回显 d**：控件下方一行 `recurrenceSummary(rule)` 实时回显（如「每周一、三、五，共 10 次」／「农历每年，永不结束」）。用可见文本、**不加** `aria-live`（子控件状态本身已被读屏读到，再上 live 会在每次改动时啰嗦）。折叠列表行仍是 08 的 `Repeat` pill（`recurrenceLabel` 频率段），不改；完整规则的回显是编辑器的职责，二者分工。

### 4. 移动端适配（触控 ≥44px、窄屏——周期是控件最多的一块）

- 所有 `<select>`/数字/日期框：`CONTROL_CLASS` 已含 `min-h-11`（44px）与 `text-base sm:text-sm`（移动端 ≥16px 防 iOS 聚焦缩放）。全宽单列堆叠，禁止横向滚动。
- 星期 chip：`flex flex-wrap gap-2`，每枚 `min-h-11 min-w-11`（44×44）。7×44＋间隙 > 320px 窄屏内容宽，故窄屏自动换行（如 5+2），保证每枚满足触控下限，而不是硬塞 7 列压到 31px 宽。
- 月内位置的「指定某日」数字框、结束条件的日期/次数框，均在其选项选中后**在下方整行展开**，不与 `<select>`/radio 挤同一行，窄屏不溢出。
- 结束条件三个 radio 行各自 `min-h-11` 命中区，相邻 ≥8px 间隙（DESIGN 间距基准）。

### 5. 可访问性

- 语义分组：外层 `fieldset`+`legend`「重复」；结束条件自成 `fieldset`+`legend`「结束」；星期集合用 `role="group" aria-label="重复的星期"` 包裹。
- 每个子控件有可见 `label`（关联 `for`/`id`）：频率、间隔、月内位置、指定日、结束日期、重复次数。
- 星期 chip：`<button type="button" :aria-pressed>` + `aria-label="周一"`…（可见字「一」，可访问名「周一」）；键盘 Space/Enter 切换。农历为原生 `checkbox` + 可见 `label`「按农历重复」。
- 结束条件为原生 radio，方向键在组内移动；选中项才渲染其输入框，输入框有自己的 `label`。
- 警告/错误经子组件自管的 `aria-describedby` 关联到相应控件（沿用 `TodoFields` 的 `describedBy` 次序：计数→提示→错误）；警告是 note 语气、错误是阻塞语气，均文字承载、不单靠颜色。
- 频率选「不重复」→ 整块子控件移除；聚焦不落空：切换后焦点留在频率 `<select>`（它始终在）。
- 校验聚焦：阻塞错误时 `validate()` 经字段 id 聚焦到频率 `<select>`（子组件用 `registerControl` 登记），与标题/时间段的聚焦路径一致。
