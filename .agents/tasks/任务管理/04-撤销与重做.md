# 撤销与重做

- 级别：直达
- 状态：开发

## 需求（产品）

- 目标与场景：误操作防线——完成/删除/编辑可 Ctrl+Z 撤销、Ctrl+Y（或 Ctrl+Shift+Z）重做。
- 范围（做 / 不做）：做 Pinia 层操作栈（命令模式、深度上限常量）；不做 回收站。
- 验收标准（逐条可检查）：
  - [ ] 撤销/重做覆盖完成、删除、编辑三类操作。
  - [ ] 撤销以逆操作进同步日志，两端数据一致；栈深受控。
  - [ ] pnpm run check 通过。

### 编排者并入项（来自 任务管理/02 评审第 1 轮，已裁决「转任务处理」）

**【前置必办】「未改动不提交」的比较口径**（`src/components/TodoItem.vue:98`）：编辑态判断「有没有改动」时比的是**原样**值而非归一化后的值——标题末尾加个空格再保存，会产生一条内容与原值完全相同的出站 op（落库结果正确，但操作是空的）。

本子任务的撤销栈直接建在这条判定上：空操作被压进栈后，用户按一次 Ctrl+Z 界面什么都不变，会以为撤销坏了。请先把「什么算一次改动」的口径定准（建议与提交时实际写入的值同源，即归一化后比较），再设计撤销栈。

补充验收标准：

- [ ] 只在标题末尾加空格后保存，不产生新的撤销条目，也不产生出站 op。
- [ ] 撤销栈中每一条都对应一次真实的状态变化，按 Ctrl+Z 必有可见效果。

### 编排者并入项（来自 任务管理/03 评审第 3 轮，已裁决「转任务处理」）

**`clearRejectionIfTouched` 仍按频道清空而非按身份收回**（`src/components/TodoFields.vue:578-584`）：03 第 2 轮已把 `applyCharCap` 改成「按提示身份收回」（`announceFormAlert` 返回它刚放上的 `PageAlert`，`retractFormAlert` 仅当它仍是当前那条时才清），但镜像位置 `clearRejectionIfTouched` 仍是无条件 `clearFormAlert()`。

评审实测的失效路径：估时 `0` 被拒 → 标题打到上限（提示条转为上限那句）→ 把估时改成 `12` → 提示条变空，而标题仍在上限且去抖仍武装、不再重新播报。计数器常驻可见，无数据后果。

修法与 03 已采纳那条同形：让 `rejection` 记住 `announceFormAlert` 的返回值，改调 `retractFormAlert`。放在本子任务是因为 04 要改的正是编辑与提交路径，与上面「改动判定口径」一条在同一段代码、同一次走查里一并验证。

补充验收标准：

- [ ] 一条提示被另一条压住后，原提示的清除条件满足时只收回自己那条，不清空当前正在显示的其他提示。
