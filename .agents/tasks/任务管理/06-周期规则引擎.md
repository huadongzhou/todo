# 周期规则引擎

- 级别：直达
- 状态：完成

## 需求（产品）

- 目标与场景：周期规则计算落 crates/domain（纯规则可单测）：每日/每周/每月/自定义间隔 + 每周一三五/每月最后一天/法定工作日。
- 范围（做 / 不做）：做 规则模型与下次时间计算；不做 农历（07）与实例落库（08）。
- 验收标准（逐条可检查）：
  - [ ] domain 单测覆盖全部规则类型与边界（跨月末、闰年、周起始）。
  - [ ] cargo test --workspace 通过；不依赖 Tauri/HTTP/数据库。

### 编排者并入项（来自 数据与同步/08 评审第 2 轮，已裁决「转任务处理」）

**【必办】ICS 导出的 `UNTIL` 缺设备本地时区偏移**（`crates/domain/src/ics.rs` 的 `recurrence_property`，联动 `src-tauri/src/lib.rs` 的 `export_calendar` 与 `src/App.vue` 的 `toInstant()`）：定时周期事件的 `UNTIL` 需要取「`until` 当日在事件自身时区的最后一秒」换算回 UTC。08 已把算式做对，但前端 `toInstant()` 一律用 `toISOString()` 写出带 `Z` 的值，domain 因此永远读到偏移 0，退回 UTC 日末——**UTC 以西的用户（如 UTC−8 的晚间任务）周期展开会少一次**。

这条路径今天不可达，仅因 `recurrence` 尚无任何界面入口；**本子任务正是让它变为可达的那个**。请在周期规则可被用户设置的同时，把导出设备的本地偏移（`getTimezoneOffset()`）随任务清单一并喂进 `export_calendar`，否则周期任务一上线，非 UTC 时区的导出即是错的。

补充验收标准：

- [ ] 在 UTC 以西时区（可通过改系统时区或注入偏移验证）设置一条晚间定时周期任务并导出，`UNTIL` 使其展开次数与界面显示的结束日一致，不少一次。

### 与 `ics.rs` 的语义收敛

引擎与 RRULE 映射逐条对齐（同一套 `crates/civil` 日期运算，不再各写一份）：

| 语义 | 引擎 | `ics.rs` |
|------|------|---------|
| 锚点本身算第一次 | 是（即使当天不符合模式，如工作日规则锚在周六） | RFC 5545 的 `DTSTART` 即如此 |
| 周起始 | 周一（契约 `Weekday` 的排列顺序） | `RRULE` 默认 `WKST=MO` |
| 每周空 `weekdays` | 取锚点的星期 | 不写 `BYDAY`，由 `DTSTART` 定 |
| 月内不存在的日子（2 月 31 日） | 跳过该月，且不消耗 `count` | `BYMONTHDAY=n` 同为跳过 |
| `on_last_day` | 当月最后一天（28/29/30/31 随月） | `BYMONTHDAY=-1` |
| 读不出的 `until` | 视为没有结束日 | 同（`and_then(parse_date)`） |
| 农历 | `Err(UnsupportedCalendar)` | 不出 RRULE，计入「只导出为单次事件」 |
| 每 N 个工作日（N>1） | 按工作日计数展开 | 不出 RRULE（标准表达不了），已在提示条告知 |

**唯一不一致（已知、不是缺陷）**：`until` 与 `count` 同时存在时，契约把两者都写成停止条件，引擎按**先到者停**；RFC 5545 禁止 `UNTIL` 与 `COUNT` 同时出现，08 已裁定保留 `UNTIL`，因此这种规则在导出文件里会比应用内多重复几次。以契约语义为准即引擎的做法；收敛办法留给界面入口那一侧——设置界面让「结束于某天」与「重复 N 次」二选一，这种规则就不会被造出来。已在 `recurrence.rs` 模块文档与单测 `a_rule_carrying_both_ends_stops_at_whichever_comes_first` 中写明，**未改 08 的既有裁定与测试**。

### 单测覆盖（33 条，`crates/domain/src/recurrence.rs`）

| 验收要求的规则类型 | 用例 |
|------|------|
| 每日 | `a_daily_rule_lands_on_every_day_from_the_anchor` |
| 每周 | `a_weekly_rule_that_names_no_day_keeps_the_anchors_weekday`、`every_other_week_skips_a_whole_week` |
| 每月 | `a_monthly_rule_keeps_its_day_of_the_month`、`a_monthly_rule_that_names_no_day_keeps_the_anchors_day_across_the_year_end` |
| 自定义间隔 | `a_custom_interval_counts_days_across_the_end_of_a_month`、`a_monthly_interval_counts_months_across_the_year_end`、`a_yearly_rule_keeps_its_day_across_the_years` |
| 一三五（`Weekday` 集合） | `monday_wednesday_friday_lands_on_each_of_them`、`the_days_of_a_week_come_in_week_order_whatever_order_they_were_stored_in` |
| 月末（`on_last_day`） | `the_last_day_of_the_month_follows_the_month_it_lands_in`（28→31→30 连着三种月长）、`the_last_day_of_february_follows_the_leap_year`、`the_last_day_of_the_month_is_the_last_day_whatever_the_anchor_was` |
| 工作日 | `every_working_day_steps_over_the_weekend`、`every_n_working_days_counts_in_working_days_not_in_days`、`the_anchor_is_an_occurrence_even_on_a_day_the_pattern_never_names` |

边界：月末在 2 月与 31 天月之间（`a_month_too_short_for_the_day_is_skipped_rather_than_moved`：1/3/5/7/8 月出、2/4/6 月跳）、闰年（`a_yearly_rule_on_a_leap_day_waits_for_the_next_leap_year` 2024→2028→2032；月末闰年 2028-02-29）、跨年（月/年/跨年末的日间隔各一条）、`interval > 1` 与 `Weekday` 集合同时存在（`an_interval_and_a_set_of_weekdays_count_weeks_together`——间隔算的是「周」不是「次」）、`until` 与 `count` 的终止（含 `until` 早于锚点、`count` 不被跳过的月份消耗、两者并存）、时区与夏令时（`a_daylight_saving_change_moves_no_occurrence`，覆盖北美 2027-03-14 与欧洲 2026-10-25：规则数的是墙上日历的天，23/25 小时的一天仍是一天）。另有拒绝类用例：农历、契约拒绝的规则（`interval == 0`、重复星期）、读不出的日期、「每年 2 月 31 日」这种永远不成立的位置（`MAX_MISSING_POSITIONS` 兜底，不死循环）。

### 【必办】ICS `UNTIL` 缺设备本地时区偏移

链路修法：`toInstant()` 仍写 `toISOString()`（不动——它是存储格式），改为在导出这一刻把设备偏移一并送下去。`src/lib/calendar-export.ts` 取 `-getTimezoneOffset()` → command 形参 `zoneOffsetMinutes` → `build_calendar(todos, generated_at, zone_offset_seconds)` → `EventWindow.zone_offset_seconds`。`ZonedInstant.offset_seconds` 变 `Option`：`Z` 与无标记都算「没说时区」，回落到设备偏移；显式 `±HH:MM`（同步下行、其他端写入）仍以值自带的为准，故 08 第 2 轮的两条既有断言未变。越界偏移 clamp 到 ±14h。
