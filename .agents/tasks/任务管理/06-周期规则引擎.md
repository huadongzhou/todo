# 周期规则引擎

- 级别：直达
- 状态：开发

## 需求（产品）

- 目标与场景：周期规则计算落 crates/domain（纯规则可单测）：每日/每周/每月/自定义间隔 + 每周一三五/每月最后一天/法定工作日。
- 范围（做 / 不做）：做 规则模型与下次时间计算；不做 农历（07）与实例落库（08）。
- 验收标准（逐条可检查）：
  - [ ] domain 单测覆盖全部规则类型与边界（跨月末、闰年、周起始）。
  - [ ] cargo test --workspace 通过；不依赖 Tauri/HTTP/数据库。

### 编排者并入项（来自 数据与同步/08 评审第 2 轮，已裁决「转任务处理」）

**【必办】ICS 导出的 `UNTIL` 缺设备本地时区偏移**（`crates/domain/src/ics.rs` 的 `recurrence_property`，联动 `src-tauri/src/lib.rs` 的 `export_calendar` 与 `src/App.vue` 的 `toInstant()`）：定时周期事件的 `UNTIL` 需要取「`until` 当日在事件自身时区的最后一秒」换算回 UTC。08 已把算式做对，但前端 `toInstant()` 一律用 `toISOString()` 写出带 `Z` 的值，domain 因此永远读到偏移 0，退回 UTC 日末——**UTC 以西的用户（如 UTC−8 的晚间任务）周期展开会少一次**。

这条路径今天不可达，仅因 `recurrence` 尚无任何界面入口；**本子任务正是让它变为可达的那个**。请在周期规则可被用户设置的同时，把导出设备的本地偏移（`getTimezoneOffset()`）随任务清单一并喂进 `export_calendar`，否则周期任务一上线，非 UTC 时区的导出即是错的。

补充验收标准：

- [ ] 在 UTC 以西时区（可通过改系统时区或注入偏移验证）设置一条晚间定时周期任务并导出，`UNTIL` 使其展开次数与界面显示的结束日一致，不少一次。
