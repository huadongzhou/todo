# 子任务

- 级别：全流程
- 状态：完成

## 需求（产品）

（在编排者预填草案基础上修订确认；实体以契约 `crates/contracts/src/lib.rs` 的 `Subtask` 与 `Todo.subtasks` 为准，本子任务不改契约。）

### 目标与场景

- 谁的什么问题：任务管理用户需要把一个任务拆成若干步骤（checklist），逐项打勾并直观看到「做到哪一步了」。
- 做什么：在任务的**编辑/详情态**内管理任务内步骤清单——新增、编辑标题、删除、勾选完成/取消完成、拖拽排序；任务在列表行上按「已完成子任务比例」展示进度。子任务是纯 checklist，仅有「标题 + 完成态」，不承载独立截止日/提醒。
- 契约事实（写需求的依据，非本任务改动）：`Subtask = { id, title, done }`；`Todo.subtasks: Vec<Subtask>`，其数组顺序即显示顺序；`validate_subtasks` 限制上限 200 项、标题非空且 ≤ 500 码点、id 不重复。

### 范围（做 / 不做）

做：

- 子任务增删改查、完成/取消、拖拽排序、进度比例展示，均发生在任务的编辑/详情态。
- 子任务的每次变更经 store 落本地持久化并产生出站同步操作（承载新的 `subtasks` 数组），且可撤销/重做（复用 04 的操作栈）。

不做（逐条列出边界与归属）：

- AI 自动拆解生成子任务清单 → 归 AI 助手母任务（TODO 14.1「落 1.4」指的是数据落点，交互不在本任务）。
- 子任务多层嵌套 → v1 不做（见「界定 a」）。
- 子任务的独立截止日 / 提醒 / 备注等属性 → 不做（契约 `Subtask` 无此类字段，纯 checklist）。
- 「复制任务携带子任务」的机制、「周期实例重置子任务」的机制 → 已分别由 05（store `duplicate`）与 08（store `buildNextInstance`）落地，本任务不重复实现，仅做集成验证（见验收 11、12）。
- 子任务进入 02 的「统一创建界面」字段块 → 不做（见「界定 c」）。
- 子任务在列表分组 / 统计 / 搜索中的呈现 → 归视图与统计模块。
- 契约变更与 bindings 重生成 → 不做（沿用既有 `Subtask` 与 `Todo.subtasks`）。

### 界定（编排者点名，逐条可检查）

- **a) 边界深度——只有一层。** 契约 `Subtask` 不含 `subtasks` 字段，多层结构在数据上不可表示；README 与母任务口径均为「步骤清单（checklist）」，本身是扁平结构。若要支持嵌套，须先改契约（属数据与同步/03 范围），v1 明确不做。
- **b) 进度定义与父子完成关系——比例派生、父子解耦。**
  - 进度 = 已完成子任务数 ÷ 子任务总数。
  - 没有子任务时：不计算、不展示进度（0/0 无意义，硬显进度条会被读作故障）。
  - 父子解耦（本子任务的主要产品决策）：勾选/取消**父任务**完成，不联动改变任何子任务的完成态；**全部子任务**完成，也不自动完成父任务；进度是纯只读派生信息，不作为父任务能否勾选完成的门槛。
  - 理由：父任务「完成」会触发既有副作用——完成满 7 天自动归档（store `runDayStart`）、周期任务完成生成下一实例（store `completeRecurring`）；让子任务勾选间接触发这些副作用不可预期。解耦是最小惊讶，且与现状 store（`status` 与 `subtasks` 互相独立）一致。
- **c) 与既有字段/操作的关系。**
  - 子任务**只在任务的编辑/详情态管理，不进入统一创建界面**：`TodoDraft`/`TodoFields.vue` 保持只装标量字段，不新增子任务。依据 README「新建待办在同一个创建界面内一次完成全部设置（标题/截止日/提醒/周期规则/标签/象限/清单）」——字段集不含子任务。子任务块作为独立于标量字段组的清单区，渲染在任务的编辑态。
  - 子任务字段仅「标题 + 完成态」（契约 `Subtask = id/title/done`），无独立截止日/提醒。
  - 删除父任务时：子任务内嵌于 `Todo`，随父任务一并删除，无独立存在与孤儿处理；撤销删除父任务时子任务随整行快照恢复（store `deleteTodo`/`insertTodo` 已保全整行）。
- **d) 排序与跨子任务关联。**
  - 子任务无排序字段，**顺序即 `subtasks` 数组顺序**（契约注释：the order of the vector is the display order）。拖拽排序通过重排数组并整体写回 `subtasks` 持久化。
  - 与 04 撤销：子任务的一次「增/删/改/勾选/排序」各记为父任务上的一次可撤销变更，Ctrl+Z 可回退最近一次子任务操作（子任务编辑属母任务撤销覆盖口径中的「编辑」）。
  - 与 08 实例生成：周期任务生成下一实例时，子任务的标题与顺序随实例带过、完成态全部重置为未完成、各子任务分配新 id——此语义已由 store `buildNextInstance` 落地，本任务保持一致、不改。
  - 与 05 复制：复制含子任务的任务时同上（新 id、完成态重置），已由 store `duplicate` 落地，本任务仅集成验证。

### 验收标准（逐条可检查）

- [ ] 1. 在某任务的编辑/详情态输入标题可新增一个子任务；新增后出现在该任务的子任务清单中，重开该任务仍在（已持久化）。
- [ ] 2. 空标题或仅空白的子任务不产生：提交时为无操作，清单数量不变。
- [ ] 3. 点击子任务完成控件可在「完成/未完成」间切换，状态持久化（重开仍保持）。
- [ ] 4. 可编辑既有子任务标题并保存，改后标题持久化；标题超过 500 码点被截断到上限（与任务标题同上限，契约 `MAX_TITLE_CHARS`）。
- [ ] 5. 可删除子任务，删除后从清单消失并持久化。
- [ ] 6. 可拖拽调整子任务顺序，顺序持久化（重开按新顺序显示）；顺序即 `subtasks` 数组顺序，无排序字段。
- [ ] 7. 有子任务的任务在列表行上展示进度＝已完成数/总数，随勾选实时更新；没有子任务的任务不展示进度。
- [ ] 8. 勾选父任务完成不改变任何子任务的完成态；全部子任务完成不改变父任务 `status`（父子解耦，见界定 b）。
- [ ] 9. 子任务的一次「增/删/改/勾选/排序」可用 Ctrl+Z 撤销、Ctrl+Y 重做（复用 04 撤销栈）。
- [ ] 10. 子任务任一变更都写本地持久化并产生出站同步操作（承载新的 `subtasks` 数组）；字段级同步下另一端可收敛（`applyRemoteUpsert` 已支持 `subtasks` 字段）。
- [ ] 11. 集成：复制一个含子任务的任务，副本携带相同子任务标题与顺序，完成态全部重置为未完成，子任务 id 全新（05/`duplicate` 既有行为）。
- [ ] 12. 集成：完成一个含子任务的周期任务生成下一实例后，新实例携带相同子任务标题与顺序，完成态重置，id 全新（08/`buildNextInstance` 既有行为）。
- [ ] 13. 子任务数量上限 200（契约 `MAX_LIST_ENTRIES`）：达到上限后新增不生效（不产生第 201 项）。
- [ ] 14. `pnpm run check` 通过；本任务不改契约、不需 `types:generate`；手动走查覆盖以上各项。

### 遗留问题（需编排者裁决）

- **父子完成联动口径**：本需求界定为「父子解耦」（界定 b）——全部子任务完成不自动完成父任务、勾选父任务不联动子任务。若产品更倾向「全部子任务完成即自动完成父任务」或「勾选父任务即把子任务全部置完成」，会牵动归档与周期实例生成副作用、并需 UI/开发相应设计，请编排者裁决后再进设计。默认按解耦推进。
- **勾选子任务是否需要非编辑态入口**（无需裁决、提示 UI/UX）：本需求把子任务管理界定在编辑/详情态，进度比例展示在折叠的列表行上。是否额外提供「不进完整编辑即可勾选子任务」的轻量入口，交 UI/UX 在规格阶段权衡，不改变本需求范围。

### 编排者裁决（2026-07-24）

1. **父子完成联动＝解耦，采纳产品界定**。理由与产品一致：父任务「完成」牵动既有副作用（`runDayStart` 满 7 天归档、`completeRecurring` 周期生成下一实例），级联触发不可预期；且与现状 store（status 与 subtasks 独立）一致。勾父不联动子、全子完成不自动完成父。这是产品默认值级别的决定，不升级为用户裁决。进度比例纯呈现，不改变父任务完成语义。
2. **复制/实例携带子任务归 05/08 既有机制，本任务只集成验证**，采纳产品对草案冲突的澄清。
3. UI/UX 阶段请就产品遗留的「非编辑态是否需要直接勾选子任务的轻量入口」给出规格判断（可做可不做，做则说明为何不破坏容器边界）。

### 0. 四个正面表态（编排者点名）

**a) 子任务列表在编辑态的结构 —— 新开独立组件，不进字段表、不进 `TodoFields`。**

- 结论：**不扩展 `FIELDS` 的 `control` 联合，也不把子任务放进 `TodoFields.vue`**；在 `TodoItem.vue` 编辑态的 `<form>` 内、`<TodoFields>` 之后，渲染一个**新组件 `src/components/SubtaskList.vue`** 作为独立清单区。
- 为什么不进 `control` 联合：`03` 的 `control` 是 input/textarea/range 三种**单值**控件，模板「只 branch 于 `kind`」；子任务是「一组可增删的行 + 勾选 + 拖拽排序」，不是单值，塞进 `control` 会把「按 `kind` 分支」的封闭小集合炸成一个特例分支，破坏字段表的形状。
- 为什么不进 `TodoFields`：`TodoFields` 同时被**创建界面（`App.vue`）与编辑态**渲染；任何进 `TodoFields`/`FIELDS`/`TodoDraft` 的东西都会一并出现在统一创建界面，直接违反**界定 c**（子任务不进创建界面）。所以子任务必须在 `TodoFields` 之外。
- 对容器边界（02 验收 B2）的影响：**不破坏**。`SubtaskList.vue` 自己承载子任务区的行结构、列数、高度与滚动；`TodoItem.vue` 编辑态只多出一行 `<SubtaskList :todo="todo" />`（外加一个「是否已展开」的布尔），**不因此获知任何标量字段名、列数、高度或滚动**——与它对 `TodoFields` 的「只知有一个字段块」保持同一姿态。`TodoDraft`/`TodoFields.vue`/`FIELDS` **零改动**。
- 子任务写入不进 `TodoDraft`：草稿仍只装标量字段（界定 c）。子任务的每次变更由 `SubtaskList` 直接调用 store（复用 `applyChange` + `recordHistory` 的既有编辑路径，开发侧新增一个承载 `subtasks` 数组的 edit 通道；本规格不设计 store，仅约定交互与提交粒度，见 c 末）。它**独立于**统一创建/编辑的「Enter 保存 / Esc 取消」草稿提交：子任务是即时落库的离散操作，不随父任务草稿的保存/取消而提交或回滚。

**b) 非编辑态待办行上的进度呈现 —— 数字徽标 `n/m`，不是进度条。**

- 结论：在 `TodoItem.vue` 折叠行现有徽标行（到期/周期/streak/未开始所在的那条 `flex-wrap` 段落）里，**加一枚只读进度徽标**：`ListChecks` 图标（16 内联档，`:size="14"` 与 Repeat/Flame 一致）+ 文本 `已完成数/总数`（如 `2/5`，`tabular-nums`），前置 `sr-only` 文案「子任务进度：」。
- 仅当 `todo.subtasks.length > 0` 时渲染；无子任务不显（界定 b：`0/0` 无意义，硬显进度条会被读作故障）。
- **不用进度条**：进度条需要一段固定宽度，会与徽标行的 `flex-wrap` 文本节奏打架、在窄屏挤占标题；且 `DESIGN.md` 是极简扁平、信息不单靠颜色/图形传达，一枚带图标+文字的数字徽标既省空间又满足「不孤用颜色」。
- 配色沿用**周期 pill 的中性 slate 分支**（进度是任务的稳定属性，不是 deadline，绝不用 urgency 红）：未完成 `bg-slate-100 text-slate-600 dark:bg-slate-800 dark:text-slate-300`；父任务已完成 `text-slate-400 dark:text-slate-500`——两支与 `TodoItem.vue` 周期 pill 现有分支逐字一致（出处：`TodoItem.vue` L363–366）。非交互，无 focus、无 Tab 停靠，尺寸不作触控目标（同 Repeat/Flame pill）。
- 顺序：`到期 → 进度 → 周期 → streak → 未开始`。到期最可行动排首；进度是「还剩多少」，第二可行动，紧随其后；周期/streak 是重复属性；未开始出现频率最低垫底。
- 会不会挤爆 / 窄屏：徽标本身极短（图标 + `n/m`，约 3–4 字宽），与其余徽标共处同一条 `flex-wrap items-center gap-2`（`TodoItem.vue` L337–339），窄屏自动折到标题下方而**不触发横向滚动**（禁止移动端横向滚动，`DESIGN.md` 间距与布局节）。徽标不与「补卡按钮行」同层，补卡仍在它自己的 `<div>`（L412）里，互不挤压。

**c) 增 / 删 / 改 / 勾选 / 排序交互（无拖拽库约束下）。**

- 结构：`SubtaskList.vue` = 顶部小标签「子任务 `n/m`」→ `<ul>` 列表（每项一 `<li>`）→ 底部「添加」输入。空态（0 项）只渲染一枚 ghost「＋ 添加子任务」触发按钮（占位与行内既有 ghost 图标按钮相当，不撑高「改错别字」这类最小编辑器，保住 `TodoItem` 既有的最小编辑器原则）；点它就地展开「添加」输入并聚焦。有 ≥1 项时直接显示标签 + 列表 + 「添加」输入。
- **新增**：底部一枚文本输入（`placeholder="添加子任务…"`）+ 右侧「添加」按钮（`Plus` 图标，触控 ≥44px）。**回车提交**（`@keydown.enter`）或点按钮均可；提交后**清空输入并保留焦点**在输入里，可连续录入多条。空标题或纯空白 → **无操作**（不产生条目，验收 2）。达上限 200 项后新增不生效（不产生第 201 项，验收 13），并经**唯一 live region**播报（见下「提示通道」）。标题上限 500 码点（契约 `MAX_TITLE_CHARS`），输入/粘贴按码点截断（复用 `TodoFields` 里 `applyCharCap` 同一套码点截断与「还可输入 n 字/已达上限」计数逻辑，仅在临近上限才出计数），粘贴超长的截断经同一 live region 播报——与标题字段行为一致（验收 4）。
- **改标题**：每行标题是**行内可编辑文本输入**（不设单独「编辑」态）。**提交粒度＝失焦（blur）或回车提交一次**，不逐键提交——这样「一次编辑」对应「一条可撤销记录」，Ctrl+Z 回退整段编辑而非一个字符（验收 9，界定 d「编辑」口径）。逐键只更新本地输入值、不落库。
- **勾选完成/取消**：每行行首一枚**原生 `<input type="checkbox">`**，`accent-sky-500`（品牌色）。选原生复选框而非父行那种自定义圆圈：① 键盘（空格）与读屏「复选框 已勾选/未勾选」语义**免费**且正确；② 方形复选框与父任务的**圆形**完成圈在视觉上区分开——正好传达「圆＝这个任务，方＝其中的步骤」，在父子解耦（裁决 1：勾满子任务不自动完成父任务）语境下避免把「勾步骤」误读成「完成任务」；③ 与设置面板既有原生复选框（`App.vue` L440/482/498）一脉相承。勾选即时落库、可撤销。完成态标题降对比 + 删除线（复用行标题完成分支：`text-slate-400 line-through dark:text-slate-500`，出处 `TodoItem.vue` L317）。
- **删除**：每行尾一枚 ghost 图标按钮（`Trash2`，`:size="20"`，触控 ≥44px），`hover:text-red-600`（破坏性用红并与常规操作分离，出处 `TodoItem.vue` L447 + `DESIGN.md` 待办行/可访问性节）。删除即时落库、可撤销。
- **排序（核心约束：`src/components/ui/` 无拖拽库，且拖拽须对键盘与读屏可用）**：采用**「上移/下移按钮为主 + 原生 HTML5 拖拽为辅」双通道**：
  - **主通道＝每行一对「上移/下移」按钮**（`ChevronUp`/`ChevronDown`，ghost，触控 ≥44px；为省宽可竖排共用一个 44px 宽槽）。理由：这是**同时**对键盘、读屏、触屏都可用、且零依赖的唯一方案。**触屏上原生 HTML5 拖拽基本不工作**（触摸不可靠触发 dragstart），所以移动端排序**必须**靠上移/下移；键盘与读屏同理。首行的「上移」、末行的「下移」置 `disabled`（`opacity-50`，`DESIGN.md` 禁用态 / `Button.vue` `disabled:opacity-50`）。按下后**焦点保持在同一按钮**（随行移动到新位置），并经 live region 播报新位次「‘X’已移到第 2 项，共 5 项」（transient），让读屏用户感知移动结果。
  - **辅通道＝原生 HTML5 拖拽**（满足验收 6 字面「可拖拽」，桌面指针增强）：行首一枚 `GripVertical` 抓手，`draggable="true"`，`dragover`/`drop` 重排数组整体写回。抓手**仅在 `sm:` 及以上显示**（近似桌面；窄屏/触屏隐藏，避免与上移下移挤成一行、也因触屏拖拽本就不工作）。抓手 `aria-hidden` 不作为键盘排序入口——键盘排序走上移/下移按钮，职责不重叠。
  - 落库粒度：一次拖放或一次上移/下移＝一条可撤销记录（验收 9/界定 d「排序」）。动效：排序默认不加动画即可满足需求；若加 FLIP，仅动 `transform`、`prefers-reduced-motion` 下降级为直接换位（`DESIGN.md` 动效节）。
- 行布局（自左至右）：`[复选框] [标题输入 flex-1] [上移/下移] [删除] [抓手(sm+)]`。移动端（<sm）无抓手，即 `[复选框][输入][上移下移槽][删除]`；触控目标 ≥44px、相邻间隙 ≥8px（`DESIGN.md`）；320px 最小视口下标题输入按 `flex-1` 收缩、控件不换行溢出（必要时动作簇 `flex-wrap` 折到输入下方，禁止横向滚动）。
- **提示通道（关键约束：不新增第二个 live region）**：子任务的「已达上限 200」「标题达上限 500 / 粘贴截断」「排序新位次」全部经 `form-alert.ts` 的 `announceFormAlert`（`source:"form"`）写入页面**唯一** `role="status"` 区（`App.vue` L366），沿用 `page-alert.ts` 的优先级仲裁——**不新建 live region**，与标题字段的 cap 播报同一通道、同一模式。

**d) 「非编辑态轻量勾选入口」表态 —— 不做，折叠行只读进度，勾选一律进编辑态。**

- 结论：**不提供**非编辑态直接勾子任务的入口；折叠行仅显 (b) 的只读进度徽标，增删改勾排全部在编辑/详情态（即行内编辑器）里。
- 理由：
  1. **父子解耦语境下防误触**：折叠行行首已有**父任务完成圈**（`toggle` 父任务，`TodoItem.vue` L286–293）。在同一行再摆子任务勾选，会与「完成整个任务」混淆；而裁决 1 明确「勾满子任务不自动完成父任务」，两种勾选后果不同却同处一行，是最容易踩的坑。把子步骤留在编辑器、与父完成圈在视觉与空间上分离，最小惊讶。
  2. **不破坏容器/行密度**：折叠行已承载 标题 + 到期/周期/streak/进度 徽标 + 补卡按钮 + 复制 + 删除。要就地勾子任务，要么加一个 disclosure 展开控件（再挤占复制/删除旁的空间），要么常驻嵌套清单（把列表变成「一墙表单」——正是 `TodoItem.vue` 顶部注释所述、行内编辑互斥要避免的形态）。两者都抬高行密度、违背 `DESIGN.md`「内容优先、单屏单一主操作」。
  3. **成本极低**：进编辑器只需点一次标题（编辑器即在其中），省下的「一次点击」不足以抵消上面两项代价。
  4. **决策可逆**：折叠行现只读，日后若数据表明有需求，可在不破坏上述边界的前提下再加 disclosure；先按最小做（起步不做）。

### 4. 移动端适配

- 触控目标：复选框、上移/下移、删除、添加按钮均补足命中区 ≥44×44px（外层 padding 撑足，不放大图标；`DESIGN.md` 触控节），相邻间隙 ≥8px。
- 拖拽在触屏：原生 HTML5 拖拽在触屏不可靠，故**抓手仅 `sm:` 显示**、触屏隐藏；触屏排序**用上移/下移按钮**（这也是键盘/读屏通道），保证移动端可完成验收 6。
- 窄屏（≥320px）：标题输入 `flex-1` 收缩，控件簇不溢出；极窄时动作簇 `flex-wrap` 折到输入下一行，**禁止横向滚动**。
- 输入高度 ≥44px、`text-base`（`sm:text-sm`）避免 iOS 聚焦缩放（沿用 `CONTROL_CLASS`，`DESIGN.md` 表单节）。
- `SubtaskList` 自身无固定高度、无内部滚动：条目多则页面变高，不在区内造二级滚动（与 `TodoFields` details 区同策，`TodoFields.vue` L846 注释）。

### 5. 可访问性

- **列表语义**：行包在 `<ul>`/`<li>`，读屏播报「列表 n 项」及位次，为排序提供上下文。
- **可访问名称**：复选框 `aria-label` = 子任务标题（读作「‘X’ 复选框 已勾选/未勾选」）；标题输入 `aria-label="子任务标题"`；上移/下移/删除按钮 `aria-label` 含标题（「上移子任务 X」「下移子任务 X」「删除子任务 X」）；添加输入 `aria-label="新子任务标题"`，添加按钮 `aria-label="添加子任务"`；抓手 `aria-hidden="true"`（非键盘入口）。进度徽标带 `sr-only`「子任务进度：」，数字 `tabular-nums` 防跳动。
- **键盘全通路**：Tab 顺序＝视觉顺序（复选框→标题→上移→下移→删除，逐行）；复选框空格切换（原生）；标题回车/失焦提交；添加输入回车新增；上移/下移回车/空格触发，首末行对应键置 `disabled`；抓手不进 Tab（键盘排序由上移/下移承担，职责不重叠）。
- **ARIA/播报**：排序后焦点留在同一按钮并经**唯一** `role="status"` 播报新位次（transient）；上限/截断经同一区播报；状态不孤用颜色——完成态同时有删除线 + 降对比 + 复选框勾态，进度徽标有图标 + 文字（`DESIGN.md` 可访问性「信息不单靠颜色」）。
- **焦点归还**：删除某行后焦点落到相邻行的删除按钮或添加输入（不落 `<body>`，与行内编辑器「returnFocus」精神一致，`TodoItem.vue` L184）。
- **编辑器内 Ctrl+Z/Y**：编辑态下文档级撤销被挂起（`App.vue` L106 `isSuspended`），此时 Ctrl+Z 是输入自身的文本撤销；子任务的离散操作（增/删/勾/排序）走 store 撤销栈的口径由 04 覆盖，本规格只约定提交粒度（见 c）使一次操作对应一条记录。
