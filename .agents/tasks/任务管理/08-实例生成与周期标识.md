# 实例生成与周期标识

- 级别：简化
- 状态：完成

## 需求（产品）

- 目标与场景：带周期的任务完成或到期后自动生成下一实例（Rust 侧执行）；列表可见周期标识与下次到期。
- 范围（做 / 不做）：做 实例生成落库与标识展示；不做 提醒触发（提醒通知母任务）。
- 验收标准（逐条可检查）：
  - [ ] 完成/到期两条路径均自动生成下一实例，规则来自 06/07 引擎。
  - [ ] 列表显示周期标识与下次到期；同步后另一端一致。

### 编排者并入项（来自 06 评审第 1 轮，已裁决「转任务处理」）

**【前置必办】`Workday` 频率的 `next_occurrence` 是 O(n²)/次**（`crates/domain/src/recurrence.rs:221`）：评审 release 实测——锚点距 `after` 26 年时单次 531 ms，126 年时 12.0 s；遍历整条序列则是 O(n³)。其余四种频率的候选推进均为 O(1)。

06 完成时 `next_occurrence` 还没有生产调用方，因此不构成问题；**本子任务是第一个调用方**，接入后这会立刻变成用户可感知的卡顿。请在接入前改为从上一候选增量推进（评审给的方向），并给出改造前后的耗时对照。

补充验收标准：

- [ ] `Workday` 频率在锚点距当前若干年的场景下，单次 `next_occurrence` 与整条序列生成的耗时与其余频率处于同一量级（须给出实测数据）。

## 规格（UI/UX）

本子任务只做列表上「周期标识」与「下次到期」的**展示**规格，作用范围＝主列表行 `src/components/TodoItem.vue` 的非编辑态。实例生成时机与落库、下一实例 `dueDate` 的计算全在 Rust/store 侧；本规格只渲染 `todo.recurrence` 与既有实例，**不在前端调用周期引擎**、**不改 `TodoFields`**（周期规则的编辑录入不属本子任务）。`todo.recurrence` 类型为 `RecurrenceRule | null`（`src/bindings/models/RecurrenceRule.ts`），已挂在 `Todo` 上。

作用范围外（本次不动，理由随附）：

- `ArchiveSection.vue`：自绘行，仅显示标题＋归档时间，不复用 TodoItem，也无需周期信息（归档是历史）。
- `TodayCard.vue`：独立投影 `TodayCardTodo`，字段已裁剪，加周期需改同步投影与载荷，超出「列表」范围；留作后续端一致性补齐。

### 会不会挤爆行——正面回答

不会。待办行是 `flex items-center gap-3`：完成圈 · 中列(`min-w-0 flex-1`) · 复制 · 删除。到期/将来徽标都在**中列内部**的 `<p class="flex flex-wrap gap-2">` 徽标行里。周期标识加进同一条 `flex-wrap` 徽标行，属中列内部换行，**不增加行的横向宽度**：宽屏与到期徽标同排，窄屏自动折到标题下第二条徽标行，绝不触发横向滚动（DESIGN「禁止移动端横向滚动」）。最坏情况只是中列多出一行约 20px 高的徽标。

### (a) 周期标识的形态与粒度

形态：**中性灰底 pill ＋ 前置 `Repeat` 描边图标 ＋ 频率文字**，例：⟳ 每周。

- 为何要图标：到期徽标与将来徽标都是「纯文字 pill」，周期标识若也做纯文字 pill 就与它们同形同族、易混。前置一个 lucide `Repeat` 图标是**日期徽标所没有的唯一视觉信号**，一眼区分「这是重复属性」而非「这是日期」；且图标不是唯一信息通道（旁有文字），符合 DESIGN「信息不单靠颜色/图标」。
- 为何用中性(normal/slate)色、不新造颜色：到期徽标三档 tone（红/琥珀/灰）表达的是**时间紧迫度**；周期是任务的**稳定属性**，无紧迫度，套红/琥珀会误导。故复用既有 normal 档灰（与将来徽标同色），与将来徽标（也是灰、纯文字「…开始」）靠前置图标区分。
- 粒度：标识只表达**频率档**（多久一次），不表达完整规则。映射（`n = interval`）：

| 规则 | 标识文字 |
|------|---------|
| daily，n=1 / n>1 | 每日 / 每 N 天 |
| weekly（含指定星期几），n=1 / n>1 | 每周 / 每 N 周 |
| monthly（含指定日/月末），n=1 / n>1 | 每月 / 每 N 个月 |
| yearly，n=1 / n>1 | 每年 / 每 N 年 |
| workday，n=1 / n>1 | 每个工作日 / 每 N 个工作日 |
| 农历 monthly / yearly | 农历每月·农历每 N 个月 / 农历每年·农历每 N 年 |
| 未识别频率（更高版本写入） | 重复（兜底） |

  - 农历只对 monthly/yearly 生效（引擎已定：农历的 daily/weekly 与公历同义），故 daily/weekly 不加「农历」前缀。
  - **刻意不枚举**具体星期几 / 月中第几天 / 月末 / until / count：这些是完整规则，属编辑表单与详情，塞进列表 pill 会溢出行宽并与表单重复。列表只回答「多久一次」，这是本规格对「要不要区分到七类粒度」的取舍——区分到频率档、不区分到规则细节。

### (b)「下次到期」的呈现——不新增第二个日期，避免混淆

关键事实：一个周期系列在列表里**同一时刻只有一个 open 实例**，它本身就是「下一次要做的那一次」。因此：

- 周期任务的 open 实例：**照常用既有到期徽标**（同一位置、同一套三档 tone、同一 `formatDueDate`）显示它自己的 `dueDate`——它就是「下次到期」。周期标识紧随其后，补充「做完还会再来」。
- **不在当前行再加一个未来日期**。同一行出现两个日期（当前截止＋下次截止）正是需求担心的混淆源（「到底哪个是我的 deadline」），也会逼前端去算 `next_occurrence`（本应在 Rust 侧）。
- 「下次到期」在**完成/顺延后由下一实例自己的行**呈现：实例 N 完成后 store 生成实例 N+1（新 open 行），它的到期徽标＝下一次到期日。于是全应用「日期徽标」永远只有一个含义——**该行自己的截止日**，语义单一、不会误读。

需求「列表显周期标识与下次到期」由此满足：标识在每个实例上；下次到期永远等于当前 open 实例的到期徽标（完成前是本次、完成后是新生成实例那一次）。

### (c) 完成一个周期实例的界面反馈

前提约束：05 已定「不新增第四类提示来源」（页面级 alert 仅 formAlert/storageAlert/exportAlert 三源，见 `pickPageAlert`）。故**完成周期任务不弹任何页面提示**，反馈全走结构与视觉。

用户勾选完成「每周·买菜」（本次 open 实例）后，界面预期：

1. 当前行按既有完成态变化：标题降对比＋删除线；到期 tone 转 `none`（完成态本就褪成无底纯文字标签）；**周期标识保留但转褪色态**（见「状态」）。该行按既有归档规则（完成满 7 天）暂留列表。
2. store 生成的下一实例作为**新 open 行出现**，带自己的到期徽标（下次到期日）＋周期标识。新行出现是静默的（无 alert）。
3. 周期标识是这里的关键可读性装置：没有它，列表里凭空多出一条一模一样的「买菜」会令人困惑；有了它，用户读得懂「打勾的是本周这次、新出现的是下周那次」。

- 新行插入位置（建议，落库归 store）：参照 05「复制」的相邻插入，把下一实例放在刚完成那行**紧邻其后**，让「同一系列」视觉成对；置顶或按序亦可，本规格不依赖具体位置，仅建议相邻以增强关联。
- 若 store 选择「生成下一实例时即归档当前完成实例」，本规格同样成立：旧行进「已归档」、新行在列表，无双行——两种落库策略下标识规格都不变。

撤销（04 在场）界面预期：`Ctrl+Z` 一次「完成周期任务」，界面应回到完成前——当前行变回 open、刚冒出的下一实例行消失。（这要求 store 把「完成＋生成」当作一个可撤销单元；撤销逻辑不在本规格，但**界面预期是「一次撤销＝完全复原」**。若 store 只回退状态、留下孤儿下一实例，用户会看到两个 open 实例，属可见不一致——提请 dev/编排者注意，见「开放问题」。）

### 五项产出

**结构与布局**

- 位置：`TodoItem.vue` 非编辑态中列的徽标行 `<p>`。把其渲染条件由 `v-if="todo.dueDate || notStarted"` 扩为 `v-if="todo.dueDate || todo.recurrence || notStarted"`（周期任务即使无到期日也要出标识）。
- 徽标顺序：到期徽标 → 周期标识 → 将来徽标（到期最具行动性排前；周期是稳定属性居中；将来态少见殿后）。
- 新增元素：一个非交互 `<span>` pill（图标＋sr-only 前缀＋频率文字），仅当 `todo.recurrence` 非空时渲染。
- 频率→文字用纯逻辑函数 `recurrenceLabel(rule): string`（见「.ts 应对」，放 `src/lib/`，只产出文字、不含类串）。
- 复用图标：`Repeat`（lucide-vue-next，描边，与既有图标同源同风格；已确认包内存在）。

**状态（默认/悬停/聚焦/加载/空/错误）**

- 默认（open 实例）：灰底 pill `inline-flex items-center gap-1 rounded-md px-1.5 py-0.5 text-xs font-medium bg-slate-100 text-slate-600 dark:bg-slate-800 dark:text-slate-300`，内含 `<Repeat :size="14" aria-hidden="true" />` ＋ `<span class="sr-only">重复规则：</span>` ＋ 频率文字。
- 完成态实例：与完成行同褪色——去底，用 `text-slate-400 dark:text-slate-500`（与完成标题同色，图标 `currentColor` 随之），pill 结构不变。以「`completed ? 褪色串 : 默认串`」两条互斥类分支写在模板（照抄标题那对互斥分支的写法，避免同权重类靠 emit 顺序定胜负）。
- 悬停/聚焦：非交互、不可聚焦；无 hover、无 focus 环、不进 Tab 序。
- 加载：无。`recurrence` 随 todo 同步到达，无异步、无骨架。
- 空数据：`recurrence` 为 null 即不渲染该 pill，无占位。
- 错误：`recurrenceLabel` 遇未识别频率（更高版本）兜底「重复」，不抛错、不空白。

**暗色适配（成对）**

- 默认：`bg-slate-100 text-slate-600` ↔ `dark:bg-slate-800 dark:text-slate-300`（DESIGN normal 档既有对）。
- 完成：`text-slate-400` ↔ `dark:text-slate-500`（既有完成标题对）。
- 图标 stroke 走 `currentColor`，随文字色在两模式自动成对，无需单独暗色值。

**移动端适配**

- 触控：标识非交互，不构成点击目标，44px 下限不适用；行内既有交互目标（复制/删除 44px、标题 min-h-11）不受影响。
- 窄屏：徽标行 `flex-wrap`，≤375px 时标识自动折到标题下第二行，无横向滚动。
- 不做窄屏截断/隐藏：最长文字如「农历每 N 个月」也短，且靠换行消化；保持端间信息一致（DESIGN 跨端一致），不按平台裁信息。

**可访问性**

- 可访问名称：pill 有可见文字即可访问；前缀 `<span class="sr-only">重复规则：</span>` 让读屏读出「重复规则：每周」，语义不靠图标/颜色单通道传达。
- 图标 `aria-hidden="true"`（装饰，语义由文字承载）。
- 非交互纯展示：无角色/焦点/键盘需求，不进 Tab 序。
- 完成反馈的读屏说明：完成动作本身由完成圈按钮 `aria-label` 从「标记为完成」翻为「标记为未完成」被读出；下一实例静默出现不额外播报（受「不新增第四类提示来源」与单一 live region 设计约束）。这是有意识的取舍、非疏漏——见「开放问题」。

### `.ts` UnoCSS 不扫描的应对（重要）

已知缺陷：UnoCSS 不扫 `.ts`，`dueDate.ts` 的 `TONE_LABEL_CLASS` 暗色类串正因此可能失效（仅当同串恰好在某 `.vue` 出现才被生成）。**应对：周期标识的所有颜色/`dark:` 类串一律作为字面 utility 写在 `TodoItem.vue` 模板里，不放进任何 `.ts` 常量表、也不引用 `dueDate.ts` 的 `TONE_LABEL_CLASS`。** 放进 `.ts` 的只有 `recurrenceLabel(rule)` 这类**纯文字**逻辑（文字不受扫描影响）。如此暗色类串必被 `.vue` 扫描生成，不重蹈 `dueDate.ts` 覆辙。（若日后该灰底组合多处重复，可由 dev 收敛为 `uno.config.ts` shortcut——shortcut 定义在配置、使用点在 `.vue`，均被正常处理；本子任务不改配置。）

### 一、前置必办：`Workday` 与农历单次 O(n²) → O(n)（增量推进）

`next_date` 的走位循环按 0,1,2… 顺序、单调不回头地问每个位置，因此把「上一位置的落点」记在 cursor 里、下一位置从它再走 `interval` 步即可，不必每次从锚点重数——`working_day_after` 与 `lunar::month_after` 都对「先走 a 再走 b ＝ 直接走 a+b」在支持区间内成立，故结果与旧算法逐位相同（204 基线单测全绿即此保证，另加两条长走位单测）。农历每年候选本就直读目标年、O(1)，只把每次调用重算的锚点农历读数改为整条缓存一次。

### 二、实例生成模型（想清楚并写明）

- **锚点＝当前实例的截止日**（不是完成时刻）：`next_occurrence(rule, dueDate, dueDate)` 取严格晚于本次截止日的下一次。理由：本仓周期规则全是固定日程（每周一三五 / 每月 15 / 工作日 / 农历生日），迟到完成也应落在原日程，与 ICS 导出展开同源（06 强调引擎↔ICS 一致）。任务的时刻（reminderAt / startsAt / endsAt / startDate）按「新旧截止日之差」整体平移，保墙钟时刻——即 06/07 说的「时刻跟着任务走、原样带过去」。
- **新实例复制口径**（参考 05 但语义为「生成下一次」）：完成态复位（status=open、completedAt/archivedAt=null、新 `createdAt`）、新 `id`、周期规则**带上并把 `count` 递减一次**、subtasks 复位 done＋换 id、attachments 换 id、`sortOrder=null`、`dependsOn` 清空；title/notes/list/tags/important/urgent/estimatedMinutes 照带；各日期字段按位移平移。
- **生成时机（两条路径）**：① 完成路径＝`toggle` 里勾选一个带 recurrence 且有截止日的 open 任务；② 到期路径＝`advanceRecurrences`，挂在与 05 `runDayStart` **同一个触发点**（`registerDayRollover`：注册即跑、午夜、回前台），但**独立于顺延开关**——顺延开关管的是「改写用户手设的截止日」，而周期任务的日期是规则定的、推进到下一次发生日是规则本职，故常开；并把周期任务从 `runDayStart` 的「顺延到今天」分支中排除，避免两条规则都动它、把它挪到日程不存在的「今天」。到期路径逐次前推（每步递减 count），前推至「≥今日」或系列终止，走 `applyChange`（与 05 一致，不入撤销栈——背景规则不是用户亲手做的、不该被 Ctrl+Z）。
- **幂等**：① 同一次完成不生成两个——`completingRecurring` Set 在 `await` 期间挡住二次点击；② 完成路径只在勾选时生成一次；③ 重启/同步重放不重复——生成只发生在本地 `toggle`/`advanceRecurrences`，`applyRemoteUpsert`（入站同步）**不生成**，后继的创建是一条带固定新 id 的 upsert op，重放按 id upsert 覆盖而非新增；到期路径为原地确定性前推，多设备各自算得同一结果、last-writer-wins 收敛。GUI 走查中「完成→生成后继→重载」后继仅一条，实测幂等成立。
- **与 04 撤销栈**：完成周期任务＝「完成 + 插入后继」两步，规格要求一次 Ctrl+Z 完全复原。为此给 `HistoryEntry` 增一个 `batch` 变体（逆序取逆、逐条应用），把两步合为一个撤销单元。这是对 04 撤销栈结构的**受控扩展**（新增一种复合条目，不改既有三种语义），判定为本任务可独立完成、无需拆分；GUI 实测一次 Ctrl+Z 后继消失＋当前行回 open、Ctrl+Y 复原，无孤儿实例。
