## 需求（产品）

<!-- 编排者预填草案：产品阶段修订确认后再进设计 -->

- 目标与场景：新建待办在一个界面完成全部设置（README 产品定义），是所有创建路径的统一落点。
- 范围（做 / 不做）：做 标题/截止日/提醒/时间段/周期/标签/象限/清单 全部设置项的创建界面；标签/象限/清单选项数据由对应母任务提供，入口在此。不做 各维度的管理界面。
- 验收标准（逐条可检查）：
  - [ ] 一个界面内完成全部字段设置并创建成功，无需二次进入编辑。
  - [ ] 各设置项与列表/详情往返一致；非法输入有校验提示。
  - [ ] pnpm run check 与手动走查通过。

### 编排者并入项（来自 数据与同步/03 评审第 2 轮，已裁决「转任务处理」）

1. **`maxlength` 与契约的计数口径不一致**（`src/App.vue:346` 联动 `src/lib/native.ts` 导出的 `MAX_TITLE_CHARS`）：输入框 `maxlength` 按 UTF-16 code unit 计数，而契约 `validate_title` 按**码点**计数，emoji 场景下输入框只肯收约一半字符。本子任务要重做统一创建界面、输入控件整体重写，请在此一次性对齐口径。
2. **标题到达上限时没有任何可见/可访问反馈**（`src/App.vue:342-352`）：用户只会发现「再打字没反应」。这属交互与文案决策，需本子任务的 UI/UX 阶段产出规格（计数器？超限提示？何时出现？屏幕阅读器如何播报？）。

补充验收标准：

- [ ] 含 emoji 与组合字符的标题，输入框实际可接受的长度与契约上限一致（按码点），不多不少。
- [ ] 到达上限时有符合 DESIGN.md 的可见反馈，且对屏幕阅读器可感知。

### 编排者并入项（来自 任务管理/01 评审第 1 轮，已裁决「转任务处理」）

1. **【前置必办】`add` 构造的出站 upsert op 漏 `reminderAt`**（`src/stores/todos.ts:150-161`）：创建任务时设的提醒**永远同步不到另一台设备**。这与 01 已修的 `update` 是同一缺陷落在兄弟路径；本子任务把提醒纳入统一创建界面，正是让这条路径被大量使用的地方，不修即带缺陷上线。
2. **表单校验错误的屏幕阅读器播报**（`src/components/TodoItem.vue:101-107`）：Enter 提交路径上焦点未移动，新出现的 `aria-describedby` 多半不会被播报，错误反馈实际只有视觉可见（点「保存」路径正常）。01 的规格明令禁止第二个 live region，因此修法必须与规格一并另议——本子任务是全流程级、有完整产品与 UI/UX 阶段，请在此重新定义表单校验反馈机制（并覆盖创建与编辑两处）。

补充验收标准（追加）：

- [ ] 经创建界面设置提醒后，出站 upsert op 带上 `reminderAt`，另一端能收到（须实测）。
- [ ] 表单校验错误在键盘提交（Enter）与点击提交两条路径上都能被屏幕阅读器感知。
