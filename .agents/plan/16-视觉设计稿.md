- 来源：用户需求「先完成 UI/UX 设计 → 下载设计图 → 后续按设计图复现」，覆盖 TODO.md 全部 15 个模块的界面表面。
- 前置方案：无（DESIGN.md 已是完整设计令牌源）。是横切设计交付，不占产品实现波次。
- 端序阶段：与实现解耦——设计稿先行，供各模块复现时参照。
- 母任务：`视觉设计稿`（已生成 `.agents/tasks/视觉设计稿/`）。

## 范围

- 以 DESIGN.md 令牌为唯一事实源，产出全应用高保真视觉稿（HTML/Artifact 渲染导出 PNG），桌面 + 移动、浅色 + 暗色成对，覆盖每屏关键状态。
- 按「屏幕/界面」而非「后端模块」拆子任务（多个模块共用一屏，如统一创建界面承载标签/象限/清单/周期/提醒），先建设计基础（令牌 + 基础组件）保证跨屏一致，再逐屏展开；15 模块的界面表面全部映射到子任务（对照见母任务「模块覆盖对照」）。
- 边界：不改产品代码，只写 `.agents/design/`；不做「复现」（按图实现归各模块后续实现）；不新增设计令牌（DESIGN.md 缺口停下报告，经确认再同步）。数据与同步（模块 6）无独立屏，其 UI 面（同步状态、存储告警条）并入主窗设计。

## 技术要点

- 产物形态：每屏一 HTML 源（自包含、内联样式用 DESIGN.md 令牌值），Browser 预览渲染后截图导出 `light.png`/`dark.png`（移动端屏另出移动版）到 `.agents/design/<序号-短名>/`。HTML 源保留，既是设计稿也是复现时可直接对照的结构参照。
- 一致性底座：子任务 01 先出「设计基础与组件库」——令牌样例（色/字/距/圆角/阴影）+ 基础组件（按钮 default/ghost、输入、徽标三档语义色、卡片 surface-card、复选框、开关、提示条、空状态、骨架）浅暗两版；02–16 一律复用其视觉语言，禁止各屏自造。
- 已编码模块（任务管理/提醒通知）：设计稿以现有文字 UI/UX 规格 + 现状代码为输入，作为回归基线，不引入与代码冲突的新视觉；未建模块：设计稿即复现前的视觉规格。
- 验证：本母任务产物非产品代码，`pnpm run check`/`cargo test` 不适用；验证 = ① 每处取值可追溯 DESIGN.md 令牌、无自造视觉；② 可访问性（正文对比 ≥4.5:1、触控 ≥44px、浅暗成对、信息不孤靠颜色）；③ 屏幕状态覆盖（默认/空/错误/加载/完成态）；④ 跨屏一致性（集成评审）。

- [ ] 每张稿的视觉取值可追溯 DESIGN.md 令牌，无自造；浅暗成对、对比达标、触控达标、信息不孤靠颜色。
