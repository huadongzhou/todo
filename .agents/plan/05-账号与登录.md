## 范围

- 5.1 注册 / 登录 / 登出 / 密码找回（邮件重置）/ 修改邮箱与密码 / 注销（含云端数据抹除）。

- 5.3 数据归属、多设备管理、服务端鉴权（/v1 全接口携带凭证）、反滥用限流（注册验证、API 限流、同步频控）。
- 边界：同步随账号绑定的同步侧改造归方案 06 后段；订阅状态绑定归方案 12。

## 技术要点

- 已锁定决策：邮箱 + 密码自建 token（不引第三方 IdP）。服务端新增用户表与凭证表（SQLite），密码哈希用成熟算法（argon2/bcrypt 选型在设计阶段定，注意 AGENTS.md 禁止随意新增依赖——此处属必要安全依赖，须在实现记录中注明理由）。
- 分层：DTO 与校验进 `crates/contracts/`（含密码强度、邮箱格式校验方法），纯规则进 `crates/domain/`，handler/service 进 `crates/server/` 以 `/v1/auth/*` 注册；token 中间件覆盖全部 `/v1/*`，现状 `/v1/sync` 无鉴权的口子在本方案关闭（保留未登录本地模式：无 token 即不同步，不报错阻断应用）。
- 邮件依赖：密码找回与注册验证需要外发邮件通道（SMTP/第三方 API），是本方案唯一外部基础设施依赖，选型与凭证管理列为首个子任务的决策项。
- 客户端：登录 UI 按 README 视图结构「登录可跳过，离线完整可用」；token 存储用系统安全存储（Tauri 侧），不落明文。
- 限流：服务端中间件（IP + 账号双维度），阈值为常量并在响应头暴露剩余额度。
