# 产品需求：截止日与提醒通知

## 背景

待办应用的核心价值在于"不错过事项"。本里程碑在已有的设置 / 主题 / 托盘基础上，补齐：

1. 为待办添加截止日和提醒时刻。
2. 到提醒时刻时通过系统通知提醒用户。
3. 明确的时间语义：截止日按用户本地日期保存；提醒按带时区的具体时刻保存。

## 适用范围

- 桌面端：使用官方 `tauri-plugin-notification` 发送本地系统通知。
- 浏览器 / 移动端：优先走插件；浏览器无插件时回退到 Web Notification API（可选降级，启动阶段先保证桌面）。
- 本期不实现服务端推送、重复提醒和跨设备同步。

## 用户故事

- 作为用户，我创建待办时可设置一个截止日和一个提醒时间。
- 作为用户，提醒时间到了，即使应用在托盘休眠，也会收到一条系统通知。
- 作为用户，已过期未完成的待办在界面中会明显标记。
- 作为用户，应用初次需要通知权限时会被请求授权；被拒绝时优雅降级，不阻塞使用。

## 验收标准

- 待办数据结构包含 `dueDate`（日历日期、可空）与 `reminderAt`（带时区时刻、可空）。
- 创建待办时可填写截止日和提醒时间；可编辑。
- 提醒时间到：发送系统通知（桌面）包含标题和剩余/逾期信息。
- 应用启动与提醒变更时正确调度 / 取消通知。
- 首次发送前请求通知权限；被拒绝时写诊断日志并静默降级，不抛错。
- 已过截止日未完成的待办在 UI 标注。

## 数据语义

- `dueDate`：本地日历日期，例如 `2026-07-20`。用于 UI 展示与逾期判定。
- `reminderAt`：提醒触发的绝对时刻（带时区），ISO8601 字符串。用于真正调度。
- 截止日当日默认视为 00:00 本地时间；如果用户只设了截止日未设提醒，默认不主动推送，仅在 UI 标注逾期。
